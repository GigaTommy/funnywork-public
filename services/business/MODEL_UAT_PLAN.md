# 企业模型中间层与 Harness 客户端测试方案

本方案验证若依管理权限、模型准入、容量、用量和客户端交互。按自动回归、页面交互、应用联调和实际推理环境分别执行，记录各层使用的版本、环境及结果。

## 1. 验收层次

| 层次 | 测试对象 | 执行方法 | 检查内容 |
| --- | --- | --- | --- |
| L1 自动回归 | Java 业务 API、Harness 适配器、准入和恢复 | `scripts/checks/run-model-uat.py`，独立 H2 与本地模拟推理服务 | 权限、票据、计量、恢复契约、构建与类型 |
| L2 页面 UAT | `ModelMiddleware.vue`、`ModelMiddlewareUsage.vue`、Harness `ModelSelect` | 模拟接口、隔离页面、`browser-uat.mjs` 与浏览器操作 | 点击、输入、键盘、分页、错误与主题交互 |
| L3 应用联调 | 测试租户门户、客户端安装包、Host 与业务入口 | 人工脚本，关联实际票据与日志 | 登录、菜单、角色权限、任务执行及后台调用 |
| L4 推理部署 | 指定硬件、引擎、模型与量化版本 | 实际协议、压力与故障场景 | 工具兼容、容量、停止语义与运行指标 |

PostgreSQL 多副本、恢复和实际推理硬件在目标部署环境单独验证。涉及其他门户模块或多租户运营时，补充相应业务、数据隔离与计费场景。

## 2. 环境与账号准备

- 开发环境：仓库声明版本的 Node、两套工作区已安装的锁定依赖、JDK 17、Maven。先读根 README 和 CONTRIBUTING。回归脚本缺少依赖时失败，不自动安装或下载推理引擎。
- L2 服务仅绑定 `127.0.0.1:19192`。模型地址使用 `.invalid` 占位；没有公网推理、账号登录、真实凭证或生产数据库写入。
- L3/L4 使用独立测试租户、数据库、缓存和测试安装包目录；由部署负责人填写测试服务地址和版本，不复用生产数据。先验证数据库备份与恢复世代配置。
- 账号矩阵：A（ADMIN，east 的模型读写与用量读）；B（模型/用量只读管理员）；U1、U2（east 员工）；U3（west 员工）；X（其他租户）；D（已停用员工）。操作权限同时核对若依菜单权限、业务角色、资源 zone，不能只看按钮是否显示。
- 模型矩阵：DeepSeek 与 Qwen 各登记实际模型 id、权重/量化版本、引擎版本、解析器、模板、协议、上下文和最大输出。初次创建停用；工具、推理、图片和流式 usage 只在验证后声明。
- 共享硬件建一个容量池：初始执行 1、每人执行 1、等待 100、每人等待 5、等待五分钟。该值是准备值，不是实测安全并发。独立硬件的第二池用于验证互不占用。
- 时间统一记录为 ISO UTC；报表检查客户端本地时间。保存浏览器、OS、安装包版本、源码提交及工作区是否有未提交改动。不得把截图、日志、凭证或数据库提交到源码目录。

## 3. 测试数据与核对口径

| 数据集 | 用途 | 核对要求 |
| --- | --- | --- |
| 基础 | 两名成员、共享容量池、启用模型，等待/运行/UNKNOWN 票据 | 取消等待减少队列；取消运行仍占用；核对 UNKNOWN 后才释放 |
| 大列表 | 1,000 条活动队列、60 名成员 | 默认50条，后页无重复；统计覆盖整池；推理并发另按硬件容量专项检查 |
| 未知用量 | 空输入/输出、缺失终止事件或初始 Messages 输出零值 | 显示未知/部分；不能转换为0或 COMPLETE |
| 空目录/空报表 | 没有模型、没有调用 | 有明确空态，无失效按钮、旧行或报错堆栈 |
| 授权变化 | 报表两次查询返回不同 zone；员工/设备授权变化 | 清空旧结果并提示重新查询；服务端独立拒绝未授权操作 |
| 故障 | 401、403、409、503、慢响应、连接拒绝、流中断、进程重启 | 区分未执行、可能执行；无自动重复写入或未知执行自动释放 |

计量核对先列明每个实际执行尝试：logicalCallId、callId/票据、输入、输出、缓存、完整性、状态。重试按实际执行次数计量；同一次累计样本覆盖，不能逐事件相加。Chat 的缓存包含在 prompt_tokens 内，Messages 的普通输入/缓存读/缓存建是不同部分。已知 token 总和必须和不完整调用数一起看。任务为客户端声明的关联分组，工具耗时尚未采集，不应当作为GPU计算时长展示。

## 4. 管理端页面 UAT（36项，可重复运行）

每项从“重置测试数据”开始，保存操作后的截图、接口审计与实际结果。接口审计仅为测试桩证据。脚本在开始下一项前关闭抽屉、等待新一轮页面挂载和可见结果，避免旧状态或动画遮挡造成伪失败。

| ID | 操作步骤 | 预期结果 |
| --- | --- | --- |
| M01 | 打开容量池；留空必填 | 初始记录可见；创建禁用 |
| M02 | 填名称/区域，创建池 | 新池可见；初始执行1、等待100，只提交一次 |
| M03 | 编辑池、改名称并保存 | zone不可修改；携带当前expectedVersion；保存后列表更新 |
| M04 | 依次选择四个 MindIE/vLLM-Ascend 预设 | 8192/2048；实际地址/id需填写；所有能力及启用关闭 |
| M05 | 选择池、填实际模型标识/地址，声明工具能力，创建 | 新部署出现但停用；工具声明保留 |
| M06 | 停用/启用原部署；复制 | 列表状态变化；复制保留模型/能力，启用恢复为关闭 |
| M07 | 取消 WAITING | 该行退出活动队列，总数减少 |
| M08 | 取消 RUNNING | 变 STOPPING；整池占用不减少 |
| M09 | 核对 UNKNOWN，先留空再填依据 | 空依据不能提交；有依据释放并记录证据 |
| M10 | 暂停/恢复准入 | 暂停说明与可用0；恢复按钮/状态正确 |
| M11 | 按 UNKNOWN 筛选 | 只显示匹配票据；整池占用仍包含运行请求 |
| M12 | 打开1000条队列；加载第二页；改筛选 | 50→100行且无重复；改条件后旧游标不能继续加载 |
| M13-401 | 注入登录失效，刷新，然后恢复 | 清空旧行，提示重登录；恢复后列表重新读取 |

| M16 | 注入慢接口、刷新 | 按钮忙时禁用；无重复提交，完成后恢复 |
| M17 | 队列首页停留超过5秒 | 出现自动刷新请求 |
| M18 | 加载队列后页，停留超过5秒 | 停止自动刷新，避免分页跳动 |
| U01 | 打开基础成员用量 | 概览/成员表显示预设的已知300输入、60输出及不完整数 |

| U04 | 调用页打开详情 | 逻辑调用、票据、设备、会话等对应当前行；无提示词和密钥 |

| ID | 操作步骤 | 预期结果 |

## 7. 私有引擎兼容与容量专项

按模型/引擎组合分别执行人工脚本 E01–E12。协议至少包含工具名与JSON参数、多工具增量、工具结果回放、多轮/推理历史、空输出/截断、stream_usage、断连、输出限制与图片限制。工具和推理解析器必须与该模型及固定软件栈一致。

容量阶段先确定能装载模型与最长请求，再测1、2、4……逐级并发，不预设1000推理并发。分别测试短输入短输出、长输入短输出、长输入长输出、工具循环、混合流量和大上下文。每轮记录硬件/软件栈、KV占用、NPU内存峰值、首次响应、tokens/s、等待p50/p95/p99、错误/拒绝、UNKNOWN数。出现OOM、超时或持续排队上涨停止加压，回到上一个稳定档。

平台压力和推理压力分开：先用模拟推理服务测100、500、1000活跃任务与有限等待，再用真实昇腾测推理槽位。等待100时超额明确429是策略生效，不是1000任务都应被接受。测试多副本必须共用PostgreSQL；连续运行至少2小时并做一个工作日的观察窗口。分别记录模拟服务吞吐与实际推理硬件容量。

执行前由产品与运维确认页面响应、等待和完成率的验收阈值，分别记录目标值与实测值，并随测试环境和版本保存。

## 8. 证据与发布判定

每项保存：用例ID、版本/环境、账号角色与区域（匿名标识）、前置状态、操作、预期、实际、PASS/FAIL/NOT_RUN/BLOCKED、截图/调用标识、缺陷编号、执行人/时间。禁止在截图或日志保存密码、真实API密钥、提示词全文和个人业务内容。

- 页面UAT通过：两条L2脚本的plannedCases全部有最新PASS，无notRun，截图存在；历史失败不删除。用真实源码组件复测，不能改成静态仿制页面。
- 回归通过：R01–R08无FAIL/BLOCKED，`--skip-build`产生的NOT_RUN仍未完成完整验收。
- 应用上线签字：人工安装包、若依权限、私有引擎、多副本及恢复场景全部完成；P0/P1缺陷清零，其他遗留有责任人与接受依据。实际推理硬件验收未完成时，保留该项为 NOT_RUN 或 BLOCKED，完成后再签署上线结论。
- 回归顺序：修复缺陷 → 重跑失败项和相邻状态 → 涉及契约时重跑R01/R02 → 发布候选版本再跑核心闭环和真实安装包。
