# 执行资源管理

管理端维护项目、资源池、用途、授权和路由，业务服务据此选择任务终端。仓库开发／验证与年报编制共用设备、节点容量及任务通道。年报资料和 COMPILE 配置见[年报参考](ANNUAL_REPORTS_R5.md)。

## 入口与职责

管理导航“工作平台 → 执行资源”，路径 `/funnyworker/resources`。短标签为“项目”“资源池”“用途”“项目授权”“路由”“终端预览”。配置页面管理组织政策；后端依政策自动选择终端、执行恢复、审查验收及交付，admin 不逐单批准。

| 页面 | 可执行操作 |
| --- | --- |
| 项目 | 创建区域内业务项目，按当前版本启用／停用 |
| 资源池 | 创建及启停资源池，搜索已有设备、添加／移出成员；成员不会自动获得项目权限 |
| 用途 | 创建 DEVELOP／VERIFY／COMPILE 用途、限定平台、启停；动作与平台保持不可变，需要调整则新建用途 |
| 项目授权 | 配置项目、仓库或年报资料、资源池、用途、指定设备或池级主体、ALLOW／DENY、有效期及启停；显式拒绝优先 |
| 路由 | 为仓库开发／验证或年报编制配置同一项目内的用途和池；保留版本冲突及跨项目约束 |
| 终端预览 | 只读取已保存政策；按资源、动作、平台和终端名称／编号查询，说明获准、可用及排除原因 |

每次更新携当前 revision。冲突不会覆盖新版本，也不会自动重试写入；页面保留编辑内容并提示刷新。保存成功后读取失败，与写入结果未知分别提示，不把刷新失败当作再次提交理由。授权和路由修改可能使正在使用的旧执行许可失效，页面明确提示。

## 预览接口与边界

- GET `/api/v1/execution-resources`：区域内项目、池、用途、成员及设备名称、授权、路由、仓库目录。
- GET `/api/v1/execution-resources/devices?after=&query=`：现有设备清单，每页最多 50 条，返回 after／hasMore；不暴露会话、文件路径或凭证。
- POST `/api/v1/execution-placement/preview`：请求 repositoryId、action、platform、query、after；返回本页候选、authorized／available、reasons、observedAt、after／hasMore，reserved 始终为 false。

预览共享 R1–R3 的权威授权校验，再解释成员、有效授权／拒绝、项目／池／用途／路由启停、账号与区域、设备撤销、任务通道、执行器／平台、在线、节点暂停、物理容量、仓库写入锁、组织／执行能力配额和旧世代恢复条件。

统计只指已加载的可见终端，不把一页设备数量说成全组织数量，也不声称已选择最终执行者。切换条件、刷新政策和写入配置时清除旧预览；迟到响应不能覆盖新条件。它不创建 Task／Attempt、不预留容量、不调用模型、不向客户端发送命令。具体任务的所有者、暂停、输入来源、预算和最终领取条件仍由原任务通道检查。

DEVELOP／VERIFY 绑定仓库，COMPILE 绑定年报资料集。用途和路由需要匹配资源类型；预览按当前已保存的静态成员及路由计算。

## 实际执行终端

“任务详情”的“执行终端”使用 GET `/api/v1/tasks/{id}/placement`：显示实际设备名称／ID、开发或验证、尝试状态、项目／资源池、用途及冻结版本、路由版本、分派时间和执行代际。历史失败尝试不冒充当前成功；无记录的历史任务明确显示未记录，等待任务显示等待原因，未知停止保留写入锁提示。

设备名称是当前登记名称；设备 ID 和冻结授权版本用于追溯后端分派与执行结果。终端按组织设备安全要求管理，后端审查与交付状态分别记录。

`tasks?taskId=...` 可直接打开任务；同页面切换任务会刷新终端记录，不能仍显示上一个任务的终端。终端记录遵循原任务的 owner、tenant、zone 和读取角色边界；管理员没有读取其他用户任务的隐式权限。

## 权限与升级

读取使用 `funnyworker:resources:read`，写入使用 `funnyworker:resources:write`。POST 预览是只读操作，使用 resources:read；创建和更新要求 resources:write，并由业务服务再要求 ADMIN 及区域权限。只读业务角色 VIEWER／OPERATOR 可在获得页面读取权限后查看授权范围内资源；不能修改政策。

任务终端记录继续使用 tasks:read，与资源配置权限分开。设备搜索不依赖 client 模块的管理权限，也不为了选择设备而暴露会话正文。

菜单登记在 `scripts/setup/ruoyi-business-menus.sql`（8022／8122），现有跨平台准备脚本会执行该文件。已有环境升级时执行同一菜单 SQL，并刷新管理页面重新载入路由；不会自动将新权限授给已有非管理员角色。业务 API 的角色与租户／区域校验不因菜单出现而省略。
