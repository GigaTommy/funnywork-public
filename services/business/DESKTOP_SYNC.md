# 桌面对话与交互同步

桌面与手机通过账号接口同步对话、文件和操作回执。仓库维护任务复用设备通道，见[维护协议](MAINTENANCE_PROTOCOL.md)；结构化经营摘要的命令、资料授权与核验见[年报协议](ANNUAL_REPORTS_R5.md)。

本协议描述电脑工作任务的归档和远程交互。原设备状态交换也承载维护任务，精确字段、身份与验收见 [原客户端维护任务接口](MAINTENANCE_PROTOCOL.md)；该路径调用 FunnyWork 内置 Agent，不启动独立客户端。手机首页独立聊天使用 `/api/account/chats` 和 V88，复用统一模型队列与账本，见 [手机聊天协议与验收](../../apps/ios/MOBILE_CHAT.md)。

FunnyWork 桌面主进程使用当前账号访问 `/api/account/sync/`。业务服务按租户和不可变 principal ID 隔离设备、原生 Session 事件、交互请求和附件。若依账号沿用 `funnyworker:desktop:read` 权限。Flyway V58、V59、V60 分别创建归档、交互及附件表，V61 增加工作区目录和设备级创建请求，V62 增加手机附件暂存记录，V63 增加桌面附件接收能力标志；部署使用已有 PostgreSQL，无需新增对象存储或开放桌面公网端口。

iOS 菜单验收需同时核对服务版本、数据库迁移及入口代理。当前手机基础功能需要包含 V61–V73 迁移的业务服务，企业模型目录同步另需 V87，独立手机聊天另需 V88；只升级手机不会补齐旧服务缺失的接口和字段。HTTPS 入口需转发 `/api/account/chats`、`/api/account/chats/`（关闭流式缓冲、读超时至少 660 秒）、`/api/account/sync/`、`/api/account/push` 和 `/api/account/push/installations/`，保留业务服务的账号鉴权及管理接口的私有访问规则，参考 `deploy/nginx/funnyworker.conf.example`。升级前备份业务数据库和现有应用包，升级后用实际账号核对设备与工作区、搜索、新建请求、重命名、归档恢复、配对、停用恢复及提醒能力响应。`MobileMenuHttpTest` 通过真实 HTTP 服务和迁移后的数据库验证这些菜单契约；线上部署与 APNs 实际投递使用目标服务和真实设备另行验收。

## 原生记录与同步游标

主进程每 15 秒枚举原生持久化目录，通过认证本地 RPC 读取固定事件前缀，等待持久化屏障后上传。服务端 `nextSeq` 是下一条事件的位置，从 0 开始；重复的相同事件返回既有确认，缺口或内容冲突使整批事务回滚。保存完整原生 v4 header、继承边界和事件，不把消息气泡、摘要或投影当作原始记录，也不上传只读观察时合成的中断补全。

客户端使用本机 revision 跳过未变化会话，每五分钟重新核对云端游标。每次同步有十秒调度预算，每会话最多处理 20 页；网络请求也有独立超时。尚未确认的前缀下一次补传。超限单个事件明确阻止该会话继续同步，不截断或跳过。历史读取不激活 Agent，也不把云端记录写回本机原生日志。

登录返回不可变 `principalId`，新账号按它分配本地目录，用户名变化不会移动已有日志。通过验证的已保存登录可以迁移尚未分配的旧账号目录；新登录不会继承同名账号的数据，重复身份映射会被拒绝。登录检查只有明确 401 或 403 才终止当前账号连接；网络中断仍保留本地记录，模型授权继续按既有有效期检查。

## 对话名称

迁移 V64 为同步会话增加 `title_revision`。目录读取返回该字段；旧服务缺少此字段时，手机客户端不显示重命名入口。`POST /api/account/sync/sessions/{id}/title` 接收 `{ "title": "名称", "revision": 0 }`，成功返回规范化后的 `title` 和递增的 `revision`。名称去除首尾空白后须为 1–160 个 UTF-16 单元且不含控制字符。仅允许同租户、同账号修改；版本不匹配返回 409，客户端须先刷新再编辑，不自动重放。

名称保存在账号的云端对话目录，来源设备离线或暂停同步时仍可修改。它不修改桌面原生 Session 日志，也不改变对话消息时间或触发 Agent。后续上传新消息保留用户设置的名称。请求超时可能已保存，客户端保留当前显示并提示错误，刷新目录可核对实际结果。

## 归档状态

V65 增加 `archived` 与独立的 `archive_revision`，不修改名称版本。`POST /api/account/sync/sessions/{id}/archive` 接收 `{ "archived": true, "revision": 0 }`，返回确认状态和递增版本；恢复使用 `archived: false`。仅同租户同账号可修改，版本过期返回 409。客户端不自动重发未知结果，可刷新核对。

归档只整理云端目录，不删除事件、附件或待执行指令，不停止来源桌面任务，也不改变消息时间；后续消息同步不会自动取消归档。目录接口继续按原游标返回全部记录，以兼容现有桌面客户端；支持归档的移动客户端分别显示日常列表和已归档列表，旧客户端可能仍显示全部记录。桌面离线或暂停同步不妨碍归档和恢复。

## 跨对话消息搜索

`GET /api/account/sync/search` 需要账号认证，只扫描当前租户、当前账号的已同步持久化消息，不唤醒桌面。参数为 `query`（去除首尾空白后非空，最多 160 个 UTF-16 单元）、`afterSession`（初始为空）、`afterSeq`（初始为 -1）、`archived`（默认 false）和可选 `deviceID`。搜索用户消息与回复的文字、附件显示名称；不搜索工具参数、推理、隐藏上下文或附件正文。匹配忽略大小写，关键词按字面值处理，不执行正则表达式。

每页按会话 ID／事件序号扫描最多 64 个事件，返回 `items`、扫描游标 `afterSession`／`afterSeq` 和 `hasMore`。`items` 包含 `conversation`（与目录字段兼容）、`seq` 和命中附近的 `excerpt`，不返回完整事件。无匹配的页仍可能有 `hasMore: true`，调用方必须使用扫描游标继续，不能用最后一个命中替代。接口按读取时的已同步记录搜索，不提供跨请求快照；搜索期间在已扫描位置追加的消息或归档范围变化，需要重新搜索。V93 为新事件保存仅含可见内容的派生正文，搜索直接读取该正文；旧事件在回填前仍按原格式解析，扫描游标及字面匹配语义保持不变。当前尚无全文索引，大量历史仍可能需要多次加载。

iOS 在左侧菜单“搜索消息”提供入口，沿用当前设备和归档筛选。每次最多连续扫描 20 页或收集至少 50 条结果，然后显示“更多结果”；只有 `hasMore: false` 且无命中时显示空结果。选择结果后通过原有事件接口读取该条完整消息，可复制、分享、预览附件，并打开所属对话定位到对应消息。客户端通过既有事件分页接口读取目标附近窗口，未读取区间显示加载入口，不为定位下载整段历史。需要部署包含此接口的业务服务；搜索不依赖来源桌面在线，但需要手机客户端能连接服务。

## 多设备交互

应用菜单的“对话历史”显示同账号各设备会话，支持分页事件、附件下载和来源设备同步暂停与恢复。窗口每五秒更新，输入草稿或编辑表单时暂停自动刷新。账号凭证、上传和下载操作均留在主进程；窗口禁用 Node、页面脚本及外部窗口，显示内容经过转义。

在线来源设备每两秒交换原生执行状态与待交付命令。远端可以排队发送文本、向当前回合补充文本、停止当前回合、回答问题及批准或拒绝一次工具操作。排队提交可以显式恢复来源设备上的冷会话；单纯查看不会恢复它。工具与模型调用始终在来源设备执行，因此该设备需要在线。此接口不迁移工作区、Git 状态或执行进程，不同步本地凭证及任意记忆文件。

每次 Host 启动生成独立 epoch。命令绑定来源设备、epoch 和唯一请求 ID，30 秒内只领取一次。相同请求重试不重复交付，内容变化返回冲突。每次交换先发布当前状态和 epoch，再逐一执行领取批次中的命令并等待持久化屏障，最后独立发送各条回执。单条回执的网络失败不会丢弃同批次的其他命令，也不会阻止后续状态发布；确认丢失只重试回执，服务端明确返回 409 时移除已失效回执。载体中断导致执行结果无法确认时显示“结果待确认”，不会自动重放工具操作。重启后旧 epoch 的未领取命令过期，已领取命令标记结果待确认。

停止和补充指令还绑定原生 `turn/start` 序号，不能误操作后续回合。审批与前台问题绑定当前原生 waterfall event ID；本地或另一设备先完成后，迟到响应不能再次决策。工具审批只支持本次允许或拒绝，不扩大持久权限。继续执行中的问题沿用原生 `userQuestions` API。

设备暂停仅停止该标识的上传及远端交互，已有历史仍可读；它不撤销账号登录或模型授权。恢复后必须由来源设备重新建立心跳和当前 epoch，旧命令不会复活。目录的在线标志基于 60 秒同步心跳，交互另要求 30 秒内的执行状态。

## 远程新建对话

手机通过设备目录选择在线桌面及其已注册工作区。桌面通过认证的原生 `workspace/follow` 流发布工作区 ID 和标题，不上传路径或成员列表；每次最多 1000 项且编码后不超过 200000 字节。流断开时清除旧目录，旧版桌面未发布工作区时不能远程创建。创建请求接受 `workspaceId` 及可选的 `model: {provider, model}`、`agentPreset`；不能指定任意文件路径、供应商地址、密钥或持久权限。设备状态单独携带 `choices: {models, presets}`，每类最多 1024 项，编码后最多 1048576 字节，只含目录标识和显示名称；工作区仍只含 ID 和标题，最多 1000 项及 200000 字节。设备状态 POST 的完整请求上限为 2200000 字节，仅该路径使用这一容量；sessions 仍不超过 900000 字节、工作区不超过 200000 字节、choices 不超过 1048576 字节。其他账号 JSON 接口保留 1 MiB 上限，避免合法目录与心跳组合后被整体拒绝。目录只按设备保存与传输一份，不在每个工作区重复。512 个企业预设及内置 standard 可以同时同步。显示名称的空白规范化，超长名称缩短；无效或重复标识、损坏预设按项隔离，不清空其他模型或预设。目录来自当前桌面的模型与预设注册表，遵循企业下发的授权和个人预设策略，目录发现异步执行，不阻塞心跳和取消。服务端提交时核对该工作区当前目录，桌面领取后再次核对；实际选择与预设绑定仍由 Harness 原生能力验证。

设备级 `create` 请求沿用唯一请求 ID、30 秒有效期、单次领取及 epoch 隔离。桌面使用 `mobile-{requestId}` 作为原生 Session ID，在对应工作区创建空对话，应用指定预设及会话模型（不修改桌面默认模型），等待持久化并注册归档后返回云端 `sessionId`；手机确认成功后进入对话，再通过既有发送入口提交内容。请求排队后需读取最终创建回执。创建过程一旦开始，任何无法确认的失败都返回 `uncertain`，不自动重新创建；回执丢失仅重试回执。用户核对对话列表后可清除手机上的待确认记录，清除不删除已创建的对话。

部署需要先应用 V61 服务端迁移并升级桌面客户端，再使用新版 iOS；服务端仍接受旧版桌面的状态格式。部署验收使用已授权账号验证设备、工作区创建及远程命令回执。

## 附件

附件使用原生 `sha256:` 标识，每次最多上传 384000 字节，按服务端字节游标断点续传，同账号相同内容只保存一份。服务端收到完整内容并校验 SHA-256 后才提供下载；客户端下载到临时文件，再次核对长度和 SHA-256 后发布到选择的位置。未完成或损坏对象不可下载。

仅允许读取对应原生日志引用的附件，路径由原生 attachment provider 解析，不接受调用方提供的本地路径。附件归属的正向验证缓存最多 128 项、60 秒，并绑定同一持久化后端的 revision；日志变化时重新验证，每个分块仍核对文件长度。当前读取需要 provider 提供原生文件路径；云端保存附件内容和精简元数据，不向远端开放工作区。默认每附件最大 32 MiB，通过业务服务配置 `funnywork.sync.max-attachment-bytes` 调整，允许 1 字节至 1 GiB。超容量或本地文件不可用会显示同步错误，不伪造完整附件。

手机附件暂存使用独立的 `/sessions/{id}/uploads/{hash}` 接口，登记文件名、MIME 类型与长度后，按字节游标上传。分块复用同账号内容寻址对象和 SHA-256 校验；登记、块重试和状态核对不会重复保存数据。未完成的暂存文件不进入桌面附件目录，也不能通过历史附件下载接口读取。每账号最多保留 100 个尚未被历史引用的暂存记录，单文件沿用附件容量配置；移除暂存记录时仅清理没有其他暂存或历史引用的对象。暂存清理和历史引用追加按账号串行，避免删除刚被历史引用的数据。已提交的附件转为会话文件引用，清除暂存记录不删除已经提交的文件；即使消息随后被拒绝，文件仍保留在会话附件目录。iOS 输入区已接入文件选择、上传进度、暂停续传和附件发送；重启后重新核对服务端状态，确认发送后清理本地附件草稿。

发送命令可携带 `attachments` 数组，每项包含 `hash`、`name`、`bytes`、`mediaType`；单次最多四个文件、合计 32 MiB，允许仅附件且 `text` 为空。服务端在排队事务内校验暂存元数据、完整性与来源桌面的 `attachmentUploads` 能力；旧版桌面默认不支持，不会静默丢弃附件。命令领取响应包含云端 `sessionId`。桌面在主进程下载并再次校验全部内容，通过认证的本地原生文件上传入口取得会话内 receipt，再把 receipt 与文字一同提交给原生 prompt。文件名不作为本地路径。文件准备失败返回 `rejected`，尚未发送文本；prompt 开始后无法确认的故障仍返回 `uncertain`，不会自动重放。接收过程检查 Host 生命周期，退出或更换 Host 后不继续提交。

## HTTP 接口

所有路径以下面的 `/api/account/sync` 为前缀，响应禁用缓存。

| 方法和路径 | 用途 |
| --- | --- |
| GET `/pending?after={id}` | 当前账号在线可操作设备上的待处理对话摘要，包含审批与回答计数 |
| GET `/devices?after={id}` | 同账号设备及当前可用工作区，每页最多 100 个设备；附带 `platform`、`lastSeen`（毫秒）与 `revoked` |
| POST `/devices/{id}/commands` | 提交绑定工作区的 `create` 请求 |
| GET `/devices/{id}/commands/{commandId}` | 核对创建结果；没有该请求时返回 `missing` |
| POST `/devices` | 注册来源设备、校验账号归属并更新同步心跳 |
| POST `/devices/{id}/revoke`、`/restore` | 暂停或恢复自己设备的同步 |
| POST `/sessions` | 注册原生 header 和继承边界，取得归档游标 |
| POST `/sessions/{id}/events` | 事务追加连续原生事件 |
| GET `/sessions?after={id}&limit=100` | 稳定 ID 游标分页目录 |
| GET `/sessions/{id}/events?offset=0&limit=100` | header、事件、下一页位置及持久归档位置 |
| POST `/devices/{id}/state` | 发布当前 epoch 和执行状态，领取待交付命令 |
| GET `/sessions/{id}/state` | 来源执行状态及交互可用性 |
| POST、GET `/sessions/{id}/commands` | 提交交互或查看最新请求结果 |
| POST `/devices/{id}/commands/{commandId}` | 确认已领取请求的执行结果 |
| POST `/sessions/{id}/uploads/{hash}` | 登记手机附件，正文为 `bytes`、`name`、`mediaType`，返回校验状态和字节游标 |
| GET `/sessions/{id}/uploads/{hash}` | 核对手机附件暂存状态和元数据 |
| POST `/sessions/{id}/uploads/{hash}/chunks` | 上传手机附件块，正文为 `offset` 和 Base64 `data` |
| DELETE `/sessions/{id}/uploads/{hash}` | 移除自己会话的暂存记录并清理无引用的对象 |
| GET `/sessions/{id}/attachments?after={hash}` | 最多 100 个附件及下一页 hash 游标；可用 `hash` 精确筛选 |
| POST `/sessions/{id}/attachments/{hash}` | 按字节游标上传附件块 |
| GET `/sessions/{id}/attachments/{hash}?offset=0` | 下载已校验附件块 |

事件请求最多 100 条且完整 JSON 不超过 900000 UTF-8 字节，header 不超过 65536 字节。运行状态最多 10000 个会话且不超过 900000 字节。命令 JSON 负载不超过 65536 字节，历史窗口另限制文本输入。附件目录只保存必要名称、类型和长度，不展开任意事件内容。

运行状态可携带 `liveAssistant`：`attemptId`、`startedAfterSeq`、`turnStart`、`text`、`truncated`。这是当前模型尝试的临时可见文本，不是已落盘消息，不包含推理片段；桌面按既有两秒状态周期发布。单条预览最多 16000 个 UTF-16 单元（不拆代理对），单次原生快照的预览 JSON 合计最多 262144 字节；完整状态超过 900000 字节时同步桥移除预览，优先交付运行状态与审批。尝试结束、流缺帧、Agent 销毁或运行时切换后预览消失；同步桥在观察到尝试结束或更换时提前同步最终历史。客户端必须同时检查 online、epoch 及 turnStart，最终 assistant/message 或 assistant/attempt 的序号超过 startedAfterSeq 后不再显示该预览，不得把预览计入离线历史或作为已完成回执。旧客户端忽略此可选字段，旧桌面仍提供最终消息同步。

生产部署沿用 HTTPS、数据库访问控制及备份策略；日志可能包含用户输入、路径和工具结果，保留策略由部署方管理。本协议不提供端到端加密。原生迁移改变已归档内容时返回冲突，不覆盖旧记录。

## 移动通知事件基础

V66 增加 `sync_notification_events` 和设备的通知基线。状态发布事务记录新出现的审批、问题及继续回答事项；同一运行实例、对话、事项和种类使用确定性编号去重，重发状态或事项消失后再次出现不会生成重复记录。首次运行实例快照建立基线，不为既有待处理事项补发通知；明确不可操作的会话不生成提醒。

任务结束依据新写入的 `turn/end` 原生事件，不根据 `running=false` 推断成功。原生 `seq` 快照表示下一个事件位置，只有基线位置及之后的事件可生成记录；初始历史、超过五分钟的旧事件、未来时间、来源状态过期或不可操作时跳过。事务失败一并撤回通知记录。事件种类为 `turn-ended`，并不表示成功；客户端应打开对话核对实际结果。

通知记录只保存账号、来源、会话、运行实例、事件编号与种类，不包含消息正文、审批理由或工具参数。服务端通过下述调度器投递事件；iOS 已接入令牌注册、订阅设置和通知点击跳转；真实后台通知仍需要 Apple 签名、APNs 配置和真机联调验证。

### APNs 提供方与手机订阅

V67 增加手机安装订阅。`GET /api/account/push` 返回提供方配置状态；`PUT /api/account/push/installations/{id}` 使用当前登录认证，提交 `secret`（安装时随机生成的 32 字节十六进制串）、APNs `token`、`environment`（`sandbox` / `production`）、`locale`（`zh-Hans` / `en`）以及 `approvals`、`questions`、`turnEnded` 三个布尔开关。响应只返回 `bindingId`、提供方 `available` 和租约 `expiresAt`，不返回令牌或安装密钥。

安装编号与密钥应保存在手机设备独立钥匙串中。已存在的编号必须提供正确安装密钥才能重新绑定；换账号或改变通知开关时更换绑定编号与订阅起点。完全相同的注册重试仅续期，不重建绑定。相同 APNs 令牌在同一环境只保留一个安装目的地，以支持重装。注册租约为 24 小时，客户端需在前台续期；注册接口不会开启系统通知权限。

`DELETE /api/account/push/installations/{id}` 同时需要账号认证与 `X-Installation-Secret`，只能删除当前账号所属安装。账号退出接口先删除该登录会话绑定的订阅，再退出身份服务；若若依退出失败，通知订阅仍保持已删除。旧账号的退出或删除不能影响重新绑定到新账号的安装。记录保留登录会话哈希、账号授权版本与绑定编号，投递器核对这些字段，不能仅按 APNs 令牌投递。

提供方配置见 [`deploy/mobile-push.env.example`](../../deploy/mobile-push.env.example)。`.p8` 私钥必须存放在仓库外的受限文件中；部分配置缺失或密钥无效时启动失败，全部留空时关闭提供方。当前 APNs 客户端使用 ES256 提供方令牌、HTTP/2、固定 Apple 域名、10 秒请求超时、不跟随重定向、4096 字节载荷限制、过期时间与折叠编号。签名缓存不超过 50 分钟；区分无效设备令牌、永久请求错误与可重试的限流／服务故障。依据：[Apple 提供方令牌说明](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns)与[发送请求说明](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)。

服务端与 iOS 已接入自动投递、注册、设置和跳转。`available` 仅说明提供方配置完整，不构成真实投递验收；测试使用临时签名密钥和模拟 HTTP 响应，没有连接 APNs。

### 自动投递与失效处理

V68 增加按事件及订阅绑定唯一的投递记录。配置 APNs 后，每 5 秒由独立工作线程扫描：一次展开最多 32 个事件、处理最多 8 次投递；网络等待不阻塞业务调度线程。只有事件发生时已经存在、同账号同租户且开关允许的订阅参与，重新绑定不会补发旧提醒。事件锁和投递锁保证多个服务实例不会并发重复展开或发送同一记录。

发送前重新核对账号启用状态、授权版本、订阅绑定及 24 小时租约、本地登录令牌的有效性与认证策略、来源设备归属和撤销状态。审批及问题还要求运行实例匹配、心跳不超过 30 秒、事项仍待处理且会话可操作；已解决或过期时取消。已持久化的任务结束记录无需设备继续在线。发送期间锁定订阅；注销、重新绑定和关闭开关完成后，旧绑定不会继续发送。已被 APNs 接受的通知无法撤回，点击后客户端仍须核对绑定并重新获取当前账号的数据。

事件有效期为 5 分钟，APNs 请求携带同样的过期时间。限流、服务故障或网络异常最多尝试 5 次，间隔为 10、20、40、80 秒，每次都重新检查资格；永久请求错误终止，无效令牌移除对应绑定。成功状态记录 APNs 接受请求；手机实际显示由设备通知设置和系统投递情况决定。网络响应丢失或进程在发送后中断时可能重试，固定折叠编号用于减少重复提醒；重传后设备仍可能收到重复提醒。事件和投递记录保留 7 天，启用调度时清理；数据库只保存响应状态码，不保存提供方错误正文、密钥或消息内容。

`MobilePushDispatcherTest` 使用模拟提供方验证去重、载荷内容、发送前的注销／重新绑定／授权／来源／事项检查、重试间隔与上限、令牌失效、事件过期及旧事件不补发；没有使用真实 APNs 或 Apple 凭证。

### 注册顺序与通知打开

V69 持久化安装注册顺序与已退出会话。iOS 在安装专属钥匙串中保存编号、密钥及递增的 revision，每次注册或删除前先递增并安全保存。PUT 传正整数 revision，DELETE 传 X-Installation-Revision（最多 9007199254740991）。较旧操作返回 409 PUSH_REGISTRATION_STALE；相同序号只允许相同请求重试。删除保留顺序记录，因此先到的取消可以阻止延迟的首次注册重新开启订阅。不同账号的首次并发注册也按持久化顺序确定最终绑定。顺序事务通过一行数据库锁串行，不包含网络操作；发送仍使用独立投递锁。

安装密钥哈希和最新序号在订阅删除后继续保留，退出会话只存凭证哈希；旧会话在业务退出开始时被禁止继续注册，包括已在过滤器通过认证但尚未进入订阅事务的请求。注册获取账号锁后重新检查授权。历史接口未传序号时按 0 处理，仅兼容尚未使用正序号的安装，不能覆盖已升级客户端。编号、密钥丢失时不能复用原编号。

通知点击仅作为打开提示，不直接执行操作。iOS 校验载荷版本、种类、安全编号、当前登录会话对应的绑定、租约和本机开关，再通过 GET /api/account/sync/sessions/{id} 获取当前账号可访问的对话（含归档）。接口同时校验租户和账号，不返回原生会话编号。账号变化或绑定变化后的延迟响应丢弃，退出清除内存路由和已显示通知。系统拒绝通知时提供系统设置入口，全部开关关闭时取消订阅；断网保留设置并显示重试，服务端取消失败时旧提醒可能继续到达；载荷只含导航标识，打开时重新校验绑定，失效绑定拒绝访问。

## 对话列表摘要与状态

V70（Java 数据迁移）为 sync_sessions 增加 preview_text、preview_seq、preview_attachment，并流式扫描既有事件补齐最新摘要；每次仅保留一个会话的最新可见候选，迁移不调用 Agent。后续 append 在事务内更新摘要，重复事件不重算，事务失败撤回摘要变化。摘要仅含 user/message 的用户来源（缺少来源时兼容旧记录）和 assistant/message 的文本／附件显示名称，排除思考与工具参数；空白和控制字符折叠，最多 400 个 Unicode 码点，不拆开代理对。只有附件且缺少名称时保留附件标记，客户端本地化显示占位。

GET /sessions 及 GET /sessions/{id} 返回摘要；列表分页继续按同步会话编号。服务端对同一页的设备状态批量读取并按设备解析一次，避免逐会话重复读取状态。task_state 可为 approval、question、waiting、running、idle，配套 task_state_remaining_ms 是心跳剩余有效时长（不超过 30000）；设备或会话状态不满足条件时省略。判断同时要求设备所属账号与租户、未撤销、运行实例存在、心跳在过去 30 秒内、会话可操作。待批准优先，之后是问题（包括 continued），再是运行中的模型容量等待（admissionWaiting > 0），最后是 running 布尔状态；idle 不表示任务成功。状态不包含审批请求、问题正文、工具参数或整个运行快照。

iOS 将剩余时长换算成本机到期时间，可见列表每 5 秒重新检查；缓存写入前移除任务状态与到期时间。列表状态不能用于批准或发送指令，点击对话后仍重新获取运行状态。ConversationOverviewTest 覆盖已有数据库补齐、可见内容过滤、Unicode 边界；DesktopHistorySyncTest 覆盖摘要重放／回滚／归属及各状态的有效性。

## 设备停用与恢复

V71 为 sync_devices 添加 access_revision，GET /devices 返回 accessRevision。POST /devices/{id}/revoke 与 /restore 接受可选对象 {"revision": 当前序号}；序号不匹配返回 409 SYNC_DEVICE_ACCESS_CHANGED。iOS 必须传序号，旧客户端无请求体仍兼容。事务在账号锁后重新验证身份，并按账号及租户锁定设备；每次实际授权变化递增序号，同一状态重复请求不改动设备运行信息。

停用令排队指令 expired、已领取指令 uncertain；它不承诺中止已在桌面执行的动作。恢复清空运行实例、心跳、工作区和快照，要求桌面重新连接，旧指令不会恢复。重复恢复已启用设备不会重置活跃运行实例。客户端不重发结果不明的请求，通过读取当前设备状态确认可操作性。没有自动跨设备切换或重新创建指令。

## 同账号扫码连接

V72 创建 sync_device_links，每个设备最多保留一个连接码。POST /devices/{id}/link 要求当前账号拥有未停用且在线的设备，返回 id、secret（32 字节随机数的小写十六进制）与 expiresIn（120000 毫秒）。新码替换旧码，服务端仅存 secret 的 SHA-256 哈希，同时绑定设备运行实例、授权序号、账号与租户。

POST /device-links/{id}/inspect 与 /confirm 使用 {"secret":"…"} 请求体，返回 id、deviceId、name、platform、epoch、expiresIn 与 confirmed；expiresIn 为剩余时长。每次重新校验当前授权、归属、过去 30 秒内的心跳、运行实例及授权序号。未知码、错误密钥或其他账号返回 404；过期、离线或设备状态变化返回 409。confirm 仅幂等记录已确认，不改变设备归属、授权或启动 Agent；结果丢失可用 inspect 核对。POST /device-links/{id}/cancel 同样传 secret，仅删除匹配的当前账号连接码，取消未知码返回 ok。

二维码格式为 funnywork://connect?v=1&server=编码后的HTTPS根地址&id=连接码编号&secret=随机密钥。桌面在主进程生成 PNG 并展示于隔离窗口，不使用外部二维码服务。iOS 扫描前不发送网络请求；只接受当前已登录服务的同源地址，无凭证、路径或额外参数的 HTTPS 根地址，然后以当前账号 inspect。用户查看设备名并确认后进入指定设备的新对话页面；实际发送仍走原有工作区、运行实例与指令校验。此流程不提供跨账号转移设备或免登录授权。

## 按消息创建分支

V73 增加设备的 session_forks 能力标志。新版桌面状态发布显式携带 sessionForks=true；旧客户端省略时保存 false。GET /sessions/{id}/state 仅在设备在线且未停用时返回 sessionForks=true。恢复设备会清除旧能力，需等待重新发布。

POST /sessions/{id}/commands 支持 kind=fork，payload 仅包含 atSeq（精确包含该位置的安全整数切点）。来源需支持分支、运行实例匹配且对话可操作；切点必须已经同步，类型为 user/message、assistant/message 或 assistant/attempt。服务端按账号锁定指令编号，重复的同一请求返回原结果；同编号的来源、实例、类型或内容不匹配时拒绝。编号上限仍为 64 字符，子会话使用 mobile-{commandId} 原生编号，不接受手机指定文件路径或子会话编号。

桌面调用原生 fork 时传入固定 childSessionId，等待持久化后核对来源与继承记录数，将子会话目录注册到当前账号，再提交 accepted 回执的云端 sessionId。服务端要求该云端对话属于同一设备、租户和账号，原生编号对应指令，isSeeded=true、来源匹配且继承记录数为 atSeq+1；子会话需已同步至切点，切点记录必须与来源一致，避免确认后打开空白或错误上下文。创建后的传输或登记失败保留为 uncertain，不自动重新执行。分支不会改写来源记录，不自动提交消息或启动 Agent。

GET /sessions/{id}/commands/{commandId} 按精确编号查询结果，不受最近 100 条列表限制；无对应请求返回 404，跨账号或对话访问同样拒绝。查询会将过期 queued 请求变为 expired，已领取但未确认的请求变为 uncertain。设备停用或重启沿用原有取消和未知结果规则。iOS 显示消息菜单入口、结果查询与跳转，交互及真实联调边界见 [iOS 说明](../../apps/ios/CLIENT_REFERENCE.md#从消息继续)。

分支继承事件中的附件引用按子对话重新登记；同账号、同租户、同哈希且已经校验完整的对象可直接复用，不重复保存文件字节。子对话仅可下载自己继承前缀中的引用，来源切点之后的附件即使已经上传也不授权给该分支，其他账号同样不能读取。原生附件仍由本地提供方保存，手机端沿用原有长度和 SHA-256 校验。

## 手机模型状态与用量

`replicaState` 发布 `admissionWaiting`（0–10000 的整数）及白名单投影 `userQuestions`、`modelSelection`、`agentPreset`、`tokenUsage`。不会复制整个投影集合。模型容量等待与手机命令交付的 queued/claimed 分别展示；取消继续使用绑定 epoch 与 expectedTurn 的既有命令，最终由桌面取消对应准入请求。在线且可操作的快照显示模型/预设；运行中优先显示 lastUsed，空闲时优先 next。目录有匹配名称时补充 modelName/agentPresetName，否则显示原标识。

手机用量使用 Harness 完整会话投影：非缓存输入、输出、缓存读取和写入四个互斥计数相加，不重复加推理或累计流式样本，不依赖手机历史分页。缺失或非法计数不展示用量，离线时不展示当前执行快照。该投影是客户端会话展示口径，管理账本仍负责按实际执行尝试计量；缺失上游 usage 与未知执行的核对不由手机推算。

V87 增加 sync_devices.model_choices_json。GET /devices 在设备级返回 choices；创建请求先核验 workspaceId，再在设备目录核验显式模型与预设。目录随每次当前 epoch 状态整体替换，恢复设备时清空。容量等待按活跃 Agent 的运行时归属逐级汇总到主会话，不使用持久化 parentSession 关系，独立恢复的分支不会被误算为子任务；子会话的控制权限保持原规则。

## 同步性能与正文投影

客户端在默认自动同步中按会话轮转，每次分配最多两页事件、两块附件，会话份额预算从读取与注册准备完成后开始计算。时间预算用于后续批次和新会话的调度，已准入会话允许首个事件或附件批次完成，避免准备或分页读取超过两秒后持续零进展；在途请求仍受原有网络超时约束，这些预算不是严格的请求截止时间。附件目录的已完成页按本地修订和云端会话保存轻量扫描位置，时间片结束后续读；修订或会话变化后重新扫描。积压或失败会话不能反复抢占目录前部的同步份额；一轮内各会话获得份额后，剩余预算最多再分配至十次轮转，避免限制单会话补传吞吐；下轮从最后尝试会话之后继续。账号重启后重新对账，不持久化服务端游标的替代值。

服务端保留成员、设备及会话锁顺序。每批最多一次只读取请求首尾序号之间的重放记录（不超过 100 条），以结构化 JSON 相等验证重放；新事件批量写入，附件引用按 hash 分组查询并批量保存。所有操作与通知事实仍处于同一事务，后部冲突回滚整批，不提前确认接收。

V93 新增 `visible_text` 和 `projection_version`，不改写原始事件。部署迁移不展开旧日志；后台默认每五秒回填最多 32 个事件，按 pending 索引读取。可通过 `funnywork.sync.projection-batch-size`（1–100）及 `funnywork.sync.projection-delay-ms` 配置速度；`funnywork.scheduling-enabled=false` 停止自动回填。回填可重启，多实例条件更新保持幂等；无可见文本也标记完成，避免反复处理工具事件。

正文投影仅减少 JSON 读取与解析成本，不等同于全文索引或企业知识库。权限、归档、隐藏内容过滤、扫描分页与旧客户端协议保持兼容。

公司级目录、独立正文权限与访问审计见 [公司会话历史管理](HISTORY_MANAGEMENT.md)。V94 将正文投影推进到版本 2，增加事件类型以区分员工和助手消息；版本 0/1 继续按既有后台批次回填，原始事件不修改。

## 远程工作区操作

新版电脑在 `choices.workspaceOperations=true` 发布能力。iOS 在远程设备页显示「管理工作区」；旧设备不出现入口。必须先升级业务服务，再升级桌面及 iOS 客户端。没有数据库迁移。

`POST /api/account/sync/devices/{id}/commands` 复用命令信封，新增 `kind=workspace`。payload.action 支持 create/rename/delete（工作区登记）、files/read/write/mkdir（工作区文件）、git/branchCreate/branchSwitch/branchDelete/worktreeAdd/worktreeRemove。除 create 外必须携带已发布的 workspaceId；操作受同账号、设备撤销、组织控制策略、运行 epoch 和 30 秒在线窗口限制。GET 对应命令回执可读取文件内容及结果，仅本账号可读。

文件目录每页 64 项，以 after 续读；UTF-8 编辑上限 64,000 字节，write 携带原内容 SHA-256 revision，新文件使用 `new` 并排他创建。工作区真实路径留在电脑端，拒绝越界、外部符号链接及 Git 元数据。保存冲突保留草稿，需重读。工作树位于相邻 `.funnywork-worktrees/`；新建后登记为独立工作区，移除只接受受管路径，Git 拒绝脏工作树，分支删除仅使用 `-d`。不提供任意 shell 或强制 Git 删除。

workspace 信封与回执最多 400,000 个 JSON 字符；其他回执仍限 4096 字符。命令领取一次，网络不确定或部分完成不自动回放。iOS 按账号和设备保存待确认命令 ID，重启只查回执；用户在电脑核对后可以解除等待。

耗时本地操作期间，`POST /devices/{id}/heartbeat` 独立发布最新状态，不领取命令，避免操作拖慢其他任务的状态显示。桌面保持 2 秒单飞心跳；目录归档轮询保持独立。

## 账号头像

`POST /api/account/avatar` 接收 `{ "image": "data:image/jpeg;base64,..." }`，仅允许已登录用户更新自己的头像。支持 PNG/JPEG、最长边 512 像素和最大 256 KB。`GET /api/account/session` 返回 `avatarUrl` 数据 URI；头像按租户和用户保存，不提供公共读取地址。客户端定期刷新账号资料，同步已保存的头像。

## 维护通道的目标安全边界

现行维护接口和客户端 VERIFY／DELIVER 是工作区实现，字段见 [维护协议](MAINTENANCE_PROTOCOL.md)。下一阶段保留原账号和设备通道，办公端只开发及提交候选；可信测试、审查和交付使用后端及受控执行身份。运行和恢复限制见[自动维护说明](MAINTENANCE_AUTOMATION.md)；本地后续方案不改变当前同步 API。

## 设备构建版本可观测性

`GET /api/account/sync/maintenance/features` 的 `clientBuild: true` 表示服务端接受状态 `choices.clientBuild`；客户端仅在明确协商后附加该字段。它复用实际安装包经 `desktopProbeBuild` 校验的 `{version, commit, tree, dirty}`，不填入后台提交或请求基线。客户端为附加元数据预留目录容量；若服务端回滚且严格拒绝新字段，客户端遇到 400 会去掉该字段重试同一状态一次并重新协商。旧客户端可继续省略该字段。

字段与当前已认证用户所属的同步设备一起存储在既有 `model_choices_json`，不新增数据库迁移。后台要求四个固定字段、版本长度/格式、40 位小写 commit/tree 和布尔 dirty；不接受额外路径或任意对象。该信息来自设备自报包清单，仅用于版本展示；授权、SYNC_CHECK 和模型调用按各自机制检查。

管理设备列表优先显示设备构建清单；缺失时兼容旧模型配置回执，否则显示未知。`clientVersionSource` 明确区分 `DEVICE_BUILD_MANIFEST`、`LEGACY_MODEL_RECEIPT` 与 `UNKNOWN`，构建 commit/tree/dirty 仅由实际清单显示。旧运行时再次上报但不携带清单时，不保留上一运行时的清单冒充当前版本。模型/策略应用状态仍各自依赖原回执，不由构建身份推断。
