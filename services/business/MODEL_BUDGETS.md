# 模型额度与预算配置参考

供后端开发、交付和运营人员查阅。模型中间层按已认证账号记录调用、预留和结算；桌面、手机聊天、标题、压缩及子任务共享计量规则，客户端传入的 device/session/task 不改变费用归属。管理端“模型限额”提供成员额度、全站预算和部署计费配置。

客户管理员操作见 [管理指南](../../manuals/ADMIN_GUIDE.md)，未交付的优化方向见 [额度优化规划（本地归档约定）](../../CONTRIBUTING.md#配置与数据)。本页描述当前实现，不是版本更新说明。

## 默认拒绝与密钥边界

- 全站初始累计预算与每日预算均为 0，并暂停推理。推广赠送初始关闭；只有运营账号显式启用后，成功登录才按活动策略发放。重新登录和更换设备不会重置消费。
- 所有部署都需要显式配置计费上界。缺少用户额度、计费、存储或预算许可时，在发送上游请求前拒绝，管理员账号也不豁免。
- `/api/account/model/publication` 已永久关闭共享密钥下发，返回 410 `MODEL_SECRET_PUBLICATION_DISABLED`。旧客户端必须升级；没有直连降级或可重新打开该接口的配置开关。
- `FUNNYWORK_MODEL_INFERENCE_ENABLED` 默认 true，让支持中间层的桌面使用短期入口凭证和模型目录。关闭此开关只禁止短期凭证；原账号票据与手机聊天仍强制经过预算校验。
- 公网 DeepSeek 的桌面部署使用中间层的 MESSAGES 或 CHAT_COMPLETIONS 固定路由，凭证只从服务端环境读取。原官方模型发布文件继续作为手机聊天的服务端模型来源；不会交给客户端。
- 两类管理端推理检查（桌面 Chat Completions、节点 Responses）均拒绝未计量推理，返回 `METERED_INFERENCE_REQUIRED`。免费模型列表发现检查保留。

**此前已经下发的 Key 无法通过代码升级收回。开放公网前必须在提供者控制台撤销旧 Key，并把新 Key 仅配置在服务端；加密包过期、卸载客户端或删除文件都不能让已提取的 Key 失效。** 本模块不远程操作提供者控制台，也不修改现网凭证。

## 金额、权限与上界

所有金额使用整数微元人民币：`1000000 = ¥1`。价格是每百万 Token 对应的微元，不使用浮点累计。

全站累计预算是长期损失上限，不随日期或账号数量重置。每日预算按 `Asia/Shanghai` 自然日计算。两种预算均包含所有未结算预占，因此在午夜不能通过遗留请求获得新的免费空间。增加累计预算表示提高总授权消费金额，保存不会清零消费。

只有部署方配置的 `FUNNYWORK_MODEL_BUDGET_OPERATOR` 对应的业务 principal（且仍具备 USER/ADMIN 身份）可读取或修改全站预算；默认 `bootstrap-admin`。公网使用若依身份时，应将该环境变量设为现有运营账号的业务 principal ID，并授予 `funnyworker:models:read/write`。普通组织管理员只能配置本租户、授权区域完全覆盖的成员额度，并查看辖区内的计费；不能修改单价、计费上界或全站预算。运营账号可在计费页按游标加载全站部署，查看部署所属租户后审核定价。计费列表只返回模型元数据，不包含上游地址、凭证引用或密钥。

已审核、直连 `https://api.deepseek.com` 的 `deepseek-flash` 部署可使用官方人民币费率（2026-09-10 版本），其他部署保留固定价格。管理端可选固定价格或 DeepSeek 官方费率；官方费率只适用于已验证的直连 Flash，不适用于代理或其他模型。每次实际开始执行时冻结输入、缓存、输出单价和时段。北京时间周一至周五 9–12 点、14–18 点为高峰，周末及国务院公布的 2026 年节假日为空闲，调休周末仍为空闲。日历/价格超出已审核年份会拒绝调用，要求更新审核，不猜测下一年度费用。

官方 Flash 高峰输入未缓存/缓存/输出为每百万 Token 2/0.04/8 元，空闲为 1/0.02/4 元。最终费用为 `ceil(((输入-缓存)×未缓存单价 + 缓存×缓存单价 + 输出×输出单价)/1000000)` 微元；每笔最多有不足 1 微元的舍入差异。Token 数据来自提供者，不按上下文长度或输出上限收费。缺失缓存用量的官方费率调用保留待核对。完整用量的失败调用也按已产生用量结算；用量缺失、截断或未知的调用保留预占，不计入实际结算。人工按上限结算会标记 `ESTIMATED_MAXIMUM`，不能称为供应商实际扣费。

`POST /api/v1/model-middleware/budgets/supplier-corrections` 仅运营账号可调用，按 `sessionId` 限定最多 100 笔已完成且用量完整的旧直连 Flash 调用。先以 `dryRun:true` 核对，随后 `dryRun:false` 应用。每笔保留原金额和改正金额、操作者、原因及时间；同步冲减累计和原日期消费，不更改授权额度。重复调用不会重复返还。历史供应商账单需单独核对，原始 Token 重算用于内部账本校正，供应商发票按供应商账单核对。

价格来源：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/ 。2026 年日历来源：https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html 。升级版本或年度前核对来源，并更新 `ModelTariff` 与对应测试。

计费必须经过指定运营账号确认。旧配置迁移时 `approved_by` 初始为 null，未经重新确认不能用于准入或执行。运营账号保存后记录审核人；在途调用仍按其预占时冻结的费率结算。

计费配置绑定 deployment ID，只能由指定运营账号修改。填写**供应商实际最大输入上下文** `inputCeilingTokens`，不得把客户端请求偏好、表单中的保守上下文准备值或预计提示词长度当成供应商最大值。价格必须覆盖当前供应商最贵输入类型（包括缓存创建）和输出/思考计费；预占采用最贵输入价格；最终结算把缓存命中与未命中分开计价。若币种不同，应使用包含汇率余量的人民币上界。提供者价格或最大上下文变更后先暂停推理、核对配置，再恢复。

发送前按完整输入上界和这次声明的最大输出 Token 预占：

`预占微元 = ceil((输入上界 × 输入单价 + 最大输出 × 输出单价) / 1000000)`

这是刻意保守的费用上界，不是精确 tokenizer。如果供应商上下文很大，体验额度可能不足以覆盖一次预占，调用会被拒绝；可选择实际有较小服务端上下文上限的部署，或提高额度。不要为了让请求通过而降低真实计费上界。请求允许文本、工具、思考消息块，以及部署明确开启 `images` 时的有效内联图片；外部图片 URL、独立上传文件引用及未计价媒体仍被拒绝；单次请求不超过 16 MiB，输出参数由服务端票据绑定，多候选仅允许 1。顶层参数采用白名单，只允许客户端执行的函数/自定义工具；提供者内置搜索、代码执行及未计价扩展被拒绝，避免产生 Token 以外的费用。

**预算约束依赖上界正确和供应商遵守上下文/输出限制。** 完整 usage 的 token 数超出配置上界、但实际费用仍在预占内时，账本按真实用量结算并记录 `MODEL_BUDGET_ANOMALY` 告警，不阻断用户后续工作。真实费用超过预占时，结算实际费用并禁用本租户的该模型部署；无法安全计算费用时保留该笔预占并隔离该部署，等待人工核对。其他部署继续受原有金额、并发与频率限制，全站暂停只由运营方明确控制。已发生的超额费用通过供应商账单核对处理。部署时同时设置供应商侧余额与消费上限，核对计费规则；发现旧 Key 泄露时立即撤销或轮换，并检查相关账单。

## 执行、结算与故障

新票据在入库前检查全站状态、成员有效额度、运营审核计费和未扣除在途预留前的余额是否足以覆盖一次预占，不合格请求不创建票据。发放执行许可时再次检查；额度在排队期间耗尽或停用的票据不能取得许可，已获准但未执行的失效许可在下一次调度时取消。并发与执行频率满额时继续排队。在途调用暂时占用资金时也继续排队，未执行许可可退回等待，保留原票据编号及等待截止时间；不会反复创建或发送模型请求。某成员资金预留不阻挡其他可执行成员；真正的消费余额不足、停用、过期及全站暂停仍拒绝执行。执行前并发竞争导致资金被预留时返回 `USER_MODEL_FUNDS_RESERVED` 或 `GLOBAL_MODEL_FUNDS_RESERVED`，与已消费耗尽区分；UNKNOWN 预留仍需运营核对，不自动释放。

最终执行事务在现有恢复锁、容量池锁、principal 锁之后获取全站预算行锁。所有进程、租户和模型池共享这一行锁；事务内同时校验用户/全站剩余额度，写入唯一 ticket 预占并把票据转 RUNNING，然后才发送网络请求。数据库断开或提交失败不会发送上游。准入及状态调度只持有恢复锁、容量池锁和预算锁，不反向获取 principal 锁。预算管理事务不反向获取容量池或 principal 锁。

用户并发（含已获准未执行许可）与最近 60 秒实际推理尝试数跨所有池、设备和会话共享；连接失败也计入一分钟尝试数。新票据独立限流，`FUNNYWORK_MODEL_ADMISSION_CALLS_PER_MINUTE` 默认 60，范围 1–10000；统计最近 60 秒成功接收的新票据，跨池共享，取消、过期及切换设备均不清零。同一 callId 的幂等重读不重复计数。拒绝请求不入账；公网网关仍应限制请求洪泛。模型目录对已配置、有效的成员额度返回较小的个人输出上限，手机聊天在生成请求与 requestDigest 前应用该上限，执行时仍重新校验。创建/取消未执行票据不收费。每次实际重试需要新票据和新预占，重复执行同一票据被拒绝。

- 完整 usage：使用预占时冻结的价格结算，释放差额；配置更新不改写在途价格。输入缓存不重复加入输入总数，reasoning 不重复加入输出。
- 缺少完整 usage：保留预占待核对，不显示为实际费用；人工上限结算标记为估算。
- 已确认 TCP/TLS 建连失败、尚未发出请求：释放费用预占，但保留限流尝试。
- 已发送后且终止未确认的失败、断流、取消、进程崩溃或执行超时：UNKNOWN 继续保留预占和并发占用，跨日及重启不退还。
- 管理员确认 UNKNOWN 上游已停止：按完整预占结算，释放并发；停止确认用于释放执行占用；费用按预占规则结算，退款另行核对。

结算与票据状态在同一事务内提交，并由 ticket ID 保证幂等。手机对话的回复持久化失败会一起回滚票据与预算结算。全站暂停、用户停用或额度过期后，看门狗会停止已有连接；HTTP 断连后提供者可能继续计费，UNKNOWN 的预留金额保持占用，待供应商执行结果核对后处理。

## 推广赠送与手工充值

如需一次性推广赠送，在“模型限额 → 推广赠送”填写适用租户 ID、选择 `WELCOME` 并设置赠送金额及非零的全站累计、每日赠送上限。迁移预设每人 1 元、余额上限 5 元、有效期 365 天、并发 1、每分钟 5 次、最大输出 262144 Token、个人每日消费上限 5 元；活动仍以 `DISABLED` 安装，全站发放上限均为 0。启用推广不解除全站推理暂停，也不自动审核模型计费。

- **一次性赠送**：仅限 V92 升级后首次开通模型额度的业务账号。迁移给已有业务 USER 写入零金额领取标记；已有手工额度的账号也不再赠送。若旧身份账号首次同步到业务系统，也按首次开通判断。账号禁用或没有授权区域不能领取。全站剩余发放预算不足 1 元时不发部分欢迎额度，留待运营提高上限后再领取。已领标记永久保留，切换模式、重新登录、跨日、重启与活动配置更新均不能重复领取。
- **每日登录领取（可选）**：`DAILY` 可配置每日 1 元、余额最高 5 元；每天累计领取不超过设定金额，按北京时间分日。余额含预留金额（累计预算减已结算），不能通过并发请求占用资金后再次领取。同日可补领未达到的每日金额，例如仅有 0.2 元空间时先发 0.2 元，消费后再领剩余最多 0.8 元。管理员充值超过余额上限时不扣钱，只暂停赠送，直至余额降到上限以下。
- **全站发放保护**：推广累计发放与每日发放各有独立上限，所有租户共享账本和锁；修改活动不清零已发放金额。额度发放与上游消费分别记账，实际调用同时受个人及全站消费预算约束。领取没有额度时返回 0，不妨碍正常登录；存储异常则不发放。
- **手工充值**：在成员页填写金额，点击“手工充值”，增加累计授权额度，保留已消费和预留金额。每笔有唯一 `requestId` 和审计；相同金额、相同请求重试不重复加钱。管理页在发送前将未确认请求保存在当前服务的浏览器本地存储；刷新、关闭或重新打开页面后先读取充值回执。已到账时仅更新余额，尚未入账时允许使用原编号和金额重试，未确认前不允许改金额；本地存储失败不会发送请求。充值不改变每日消费上限、有效期、并发、输出或停用状态；未配置的账号需先保存额度策略。该入口不执行在线收款。
- 自动发放接在桌面及 iOS 的成功密码登录之后；`GET session` 不写账。已有登录会话也可通过认证的 `POST claim` 领取，无需退出账号。Mac 和 Windows 的账号菜单、iPhone 和 iPad 的账号设置均提供余额、预留金额、今日可用额度与领取按钮；打开页面读取服务端实时状态，不缓存为离线可消费余额。

赠送金额也必须覆盖目标模型的单次最大预占。检查上面的费用公式；若 1 元不足，使用提供者确实限制较小上下文的部署，或调整赠送金额，不能虚报价格或输入上界。过期、停用的已有额度不会被每日领取复活，需要管理员确认有效期和状态。

## API

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/api/account/inference/budget/claim` | POST | 本账号领取；返回 `credited_micros` 和最新 `budget`，重复领取受持久化记录限制 |
| `/api/v1/model-middleware/budgets/promotion` | GET / PUT | 仅运营账号管理活动；返回累计和当日发放量 |
| `/api/v1/model-middleware/budgets/users/{owner}/topups/{requestId}` | GET | 核对手工充值；返回 `POSTED/ABSENT`、原金额及最新成员预算；与充值相同的租户和区域权限 |
| `/api/v1/model-middleware/budgets/users/{owner}/topups` | POST | 辖区管理员手工加额度，字段 `amountMicros`、`requestId`（16–64 位字母数字、连字符或下划线）、`expectedVersion` |
| `/api/account/inference/budget` | GET | 本账号已结算、预占、剩余累计额度；短期入口凭证也可读取 |
| `/api/v1/model-middleware/budgets/global` | GET / PUT | 仅部署指定运营账号，全站预算和暂停状态 |
| `/api/v1/model-middleware/budgets/deployments?after=&limit=50` | GET | 运营账号读取全站计费目标；组织管理员仅读取本租户辖区部署 |
| `/api/v1/model-middleware/budgets/users?after=&limit=50` | GET | 本租户辖区内业务成员，候选扫描游标分页 |
| `/api/v1/model-middleware/budgets/users/{owner}` | GET / PUT | 成员额度与限流策略 |
| `/api/v1/model-middleware/budgets/prices/{deployment}` | GET / PUT | 部署计费上界；PUT 仅指定运营账号，GET 允许辖区管理员只读 |

账号预算返回个人 `promotion`：`mode`、`grant_micros`、`balance_cap_micros`、`claimed_micros`、`available_micros`、`can_claim`。不返回全站活动预算或其他成员资料。POST claim 返回最新个人预算和本次入账金额；客户端只据此更新领取结果，最终准入仍重新检查实际费用。

成员列表还返回 `canManageGlobal`、`canManagePricing`。页面仅向运营账号显示全站预算及计费编辑入口；全站范围的 403 只关闭该范围，不清除仍有权管理的成员和部署。401 或整个模块读取权限失效仍清理全部缓存。

PUT 使用 `expectedVersion` 防止并发覆盖。新成员和新计费项版本为 0，首次保存后为 1；全站初始版本为 0。已结算/预占计数只由推理账本修改，不能通过策略 API 清零。

活动请求字段：`tenantId`、`mode`（`DISABLED/WELCOME/DAILY`）、`grantMicros`、`balanceCapMicros`、`totalMicros`、`dailyMicros`（全站发放上限）、`userDailyMicros`（新钱包每日消费上限）、`validityDays`、`concurrency`、`callsPerMinute`、`maxOutputTokens`、`expectedVersion`。模板仅应用于新钱包，已有钱包继续使用管理员策略。

全站请求字段：`totalMicros`、`dailyMicros`、`paused`、`expectedVersion`。

成员请求字段：`totalMicros`、`dailyMicros`、`concurrency`（1–32）、`callsPerMinute`（1–600）、`maxOutputTokens`、`expiresAt`（毫秒时间戳）、`enabled`、`expectedVersion`。并发和频率应覆盖主任务、标题、压缩等正常请求组合，并受容量池统一调度；不再以并发 1、每分钟 5 次作为通用体验建议。有效期由活动或合同设定；实际金额应覆盖目标模型的单次预占。

计费请求字段：`inputMicrosPerMillion`、`outputMicrosPerMillion`、`inputCeilingTokens`、`expectedVersion`。默认不提供可能过期的供应商价格。

常见拒绝码：`MODEL_BUDGET_PAUSED`、`MODEL_BUDGET_REQUIRED`、`MODEL_BUDGET_EXPIRED`、`MODEL_PRICE_REQUIRED`、`USER_MODEL_BUDGET_EXHAUSTED`、`GLOBAL_MODEL_BUDGET_EXHAUSTED`、`USER_INFERENCE_BUSY`、`USER_INFERENCE_RATE_LIMIT`、`USER_MODEL_ADMISSION_RATE_LIMIT`、`USER_OUTPUT_LIMIT`。

## 升级与验证

1. 备份数据库，停止所有旧业务副本及在途请求，升级支持中间层的客户端与业务服务。不要让不认识 V92 的旧业务进程同时运行；旧进程可能不执行新准入检查或仍允许修改已审核价格。
2. 轮换此前可能下发的共享 Key，设置运营 principal、上游 origin 和服务端凭证，执行迁移 V90、V91、V92。旧安装的初始预算也为 0 且暂停，不沿用无限调用。
3. 在管理端配置固定部署，由指定运营账号审核准确计费上界，再配置少量测试成员额度，设置全站每日与累计预算，最后关闭“暂停全站推理”。新建部署或官方来源的新版本有新的 deployment ID，需要重新配置计费。
4. 使用测试账号检查一次完整调用、超额拒绝、跨设备并发、断流、暂停与 UNKNOWN 核对。注册风控、验证码发送限流及短信成本保护属于独立模块；开启赠送前应同时设置全站发放上限与消费上限，批量注册最多消耗已授权活动预算。

回归：`sh scripts/mvn.sh -Dtest=ModelBudgetsIntegrationTest,ModelMiddlewareIntegrationTest,MobileChatsIntegrationTest,DesktopModelPublicationTest,DesktopModelReleaseIntegrationTest,DesktopModelChecksTest,ManagedConnectionsIntegrationTest test`。

`ModelBudgetsIntegrationTest` 可使用 `FUNNYWORK_MODEL_BUDGET_TEST_DB_URL/USER/PASSWORD` 在现有 PostgreSQL 数据库中创建唯一隔离 schema，并在结束时删除该测试 schema。覆盖两个独立中间层/预算服务实例跨租户争抢全站预算、跨池并发准入限流，以及同一账号并发执行时的 principal/预算锁顺序。未设置时使用 H2，不把 H2 检查当成 PostgreSQL 并发证据。

管理页可在 `apps/management/uat/model-middleware/` 的隔离页面选择“模型限额”进行真实组件操作；测试数据不连接真实供应商、不消费真实额度。

## 长上下文与默认输出

标题等辅助请求的输出长度是单次请求偏好，不是成员可用额度，也不限制业务报告长度。它们仍经过相同准入与计费流程；请求参数及提供者适配由客户端模型模块负责。

新部署表单默认 1000000 上下文和 65536 输出，必须按所接模型实际能力调整，不能把表单默认值视为所有模型的保证。DeepSeek 官方发布的 `deepseek-flash`、`deepseek-v4-pro` 手机入口使用 1000000 上下文，其他模型使用 131072。发布输出支持 128–262144，默认 65536。成员及推广默认输出 262144、并发 32、每分钟 600 次，有效期 365 天，避免另外以小 Token 上限限制正常生成；已保存的成员策略与部署不会被自动覆盖。V96 仅升级旧的 2048 输出、并发 1、每分钟 5 次的推广模板，不增加赠送或消费金额。

桌面与手机仍使用部署能力和显式成员策略中较小的输出上限。手机不再额外压低到 4096。执行请求仅在推理路由允许最多 16 MiB，其他 API 保持原大小限制；部署时同步更新网关请求大小。并发排队、有效期、停用状态与使用额度继续由既有策略管理。费用按真实模型上下文的审核计费上界预占，完整用量返回后结算；扩大上下文会提高单次资金预占，不能通过缩小计费上界来绕过金额控制。

参考：[DeepSeek 官方模型规格](https://api-docs.deepseek.com/quick_start/pricing/)。
