# 桌面模型发布

桌面模型与执行节点使用不同协议。节点的 Responses API 配置继续通过模型配置入口维护；桌面支持现有 DeepSeek 官方接口。管理端“桌面模型发布”保留官方模型设置与历史管理，供手机聊天的服务端目录使用。V90 起 `/api/account/model/publication` 返回 410 `MODEL_SECRET_PUBLICATION_DISABLED`，不再向任何客户端下发共享 API Key。桌面使用模型中间层目录、短期凭证及[模型预算](MODEL_BUDGETS.md)。

## 升级与凭证

业务服务 Flyway V74 创建版本与检查记录，不复制私有密钥。升级前备份业务数据库。现有 `FUNNYWORK_DESKTOP_MODEL_FILE` 继续提供租户、签名密钥与公钥；尚未通过管理端发布时，沿用文件中的模型设置和版本。

第一次发布时保存部署基线，并创建更高版本。此后模型、地址、思考模式、输出上限和版本以数据库最新发布为准；直接改动文件中的同名字段不会覆盖管理端发布。文件仍提供签名材料，以及 `DEPLOYMENT_DEFAULT` 引用对应的 API Key。部署方也可设置 `FUNNYWORK_MODEL_` 开头的环境变量，并在发布界面填写该名称。页面不接收或返回密钥，数据库只存引用。环境变量变更通常需要重启服务进程。

服务会验证签名密钥配对和凭证就绪后才允许发布。不要随意更换已有客户端固定的签名公钥；本功能不提供自动公钥轮换。

## 发布、检查与恢复

- GET `/api/v1/desktop-model-releases`：当前设置、凭证是否就绪、最近 100 个版本和 20 个检查结果。
- POST 同路径：提交 `expectedVersion`、`endpoint`、`model`、`thinking`、`maxTokens`、`credentialRef`。过期版本返回冲突。首次发布保存可恢复的部署基线。
- POST `/api/v1/desktop-model-releases/rollback`：提交当前 `expectedVersion` 与历史 `targetVersion`；复制历史设置为更高的新版本，保持客户端防降级校验。
- POST `/api/v1/desktop-model-releases/check?inference=false`：提交同样的设置，对当前草稿查询模型列表。`inference=true` 返回 409 `METERED_INFERENCE_REQUIRED`，防止绕过预算；推理验证应从已配置额度的客户端发起。检查只记录结果和非敏感设置，不保存模型响应内容。凭证发生变化后重新执行连接检查，保存新的核对结果。

管理身份需要 `funnyworker:models:read` 或 `write` 权限，以及业务 ADMIN 身份。桌面发布影响整个租户，因此管理员的业务区域必须覆盖该租户全部已有用户，包括已停用账号。执行节点单独配置仍按原有区域权限检查。客户端继续使用桌面读取权限与独立业务授权。

服务端发布版本与设备加载状态分别记录。旧版密钥配置续期已停止，设备需升级至支持中间层的版本。此前下发的密钥即使删除本地包仍可能被提取，部署前必须在提供者控制台撤销旧 Key 并替换服务端凭证。恢复历史版本也不会恢复历史密钥，只会重新解析当下的凭证引用。

## 验证范围

自动测试覆盖密钥下发接口拒绝、部署基线恢复、单调版本、过期提交、租户和区域边界、凭证不可用、模型响应脱敏和检查后的权限撤销。模拟接口测试不证明生产供应商凭证或真实推理可用；发布管理员可在目标部署上执行相应检查。

检查请求格式依据 [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)；服务端仅接受客户端现有协议允许的官方目标地址。

## 执行节点配置历史

V75 为已有节点模型配置保存迁移基线，保留原配置和版本。后续每次保存写入历史记录；GET `/api/v1/model-profiles/{id}/history?before=0&limit=50` 按版本倒序分页，POST `/api/v1/model-profiles/{id}/restore` 用 `expectedVersion` 与 `targetVersion` 将历史设置恢复为新版本。恢复包含区域与启停状态，但不恢复节点本地私有凭证。

查看历史需要当前配置区域权限，并仅返回管理员有权访问的历史区域；恢复同时检查当前与目标历史区域，不能通过旧版本跨越区域权限。迁移前没有记录的更早版本不会被虚构为历史。

节点页面保留不调用推理的“检查连接”。Responses 推理检查也返回 `METERED_INFERENCE_REQUIRED`，不能使用其他模型配置入口绕过预算。检查仍受部署允许名单限制，不跟随重定向，结果写入脱敏审计。

## 客户端加载回执

以下为升级前已有设备回执的兼容处理；V90 不再签发新密钥包。V78 保存下发模型的公开设置、设备公钥指纹、签名摘要、有效期和加载回执，不存储模型凭证或签名私钥。签名摘要是下发包签名原始字节的 SHA-256，不修改原加密信封协议。

POST `/api/account/model/receipt` 接收 `device`、`syncDevice`、`version`、`digest`、`clientVersion`、`loaded`。只有同一账号未撤销的同步设备、最新已下发包、未过期且仍为当前发布版本才接受。`loaded=false` 关联设备并报告运行设置尚未匹配；`loaded=true` 更新最后确认版本。该上报不是硬件证明，也不表示推理调用已成功。

桌面在运行中的 Host 设置里核对默认提供方、模型、服务地址、思考开关和最大输出参数，每分钟最多发送一次回执。更新或检查回执失败不会关闭有效会话。旧服务返回回执接口 404 时兼容运行，后台不虚构加载状态。模型配置按原续期周期获取；发布新版本后，尚未续期的客户端显示等待更新。
