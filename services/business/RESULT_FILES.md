# 固定版本结果文件

实现范围是 Word（DOCX）、Excel（XLSX）、PowerPoint（PPTX）和 PNG 的原文件发布、跨端同步、iOS 预览与固定版本修改反馈。桌面是当前文件生成执行环境；手机聊天通过“交给电脑生成”选择已授权、可用电脑并确认任务草稿。手机聊天本身不因此获得本地文件系统或 Office 生成环境。

## 使用与交互

1. 使用同一账号登录电脑与 iOS，授权该电脑连接业务服务。手机可从聊天的“交给电脑生成”入口选择工作区、模型及任务内容；确认创建后进入电脑任务，原聊天提供“相关电脑任务”入口。未完成创建会保留草稿与绑定该请求的来源聊天；从任何创建入口恢复都会在清除已接受回执前保存关联，联网后幂等确认。普通任务和取消请求不会沿用其他任务的来源聊天。存在待恢复创建时，先完成或取消，防止错误关联。
2. Agent 生成最终文件后调用 `publish_result`。对话出现原文件名、固定版本和预览状态。结果声明、附件上传完成、预览准备完成、任务运行完成是独立状态。
3. iOS 结果目录显示原文件同步情况。Word/PPT 默认查看 PDF；Excel 默认查看分工作表的已保存值；PNG 支持缩放。用户可下载或分享原文件，也可分享 PDF 预览。预览失败保留原文件；重试预览加入对话草稿，由用户发送给电脑。
4. “提出修改”记录结果标识、版本、原文件 SHA-256 及位置；PDF 保留当前页码，工作表可引用具体单元格，图片可以填写区域描述。反馈加入现有对话草稿，保留用户其他输入，不自动发送。Agent 通过 `inspect_result` 读取指定原文件快照，复制到新的工作区文件后修改，再用 `resultId` 与 `expectedVersion` 发布新版本；过期版本预期被拒绝。打开旧版本不会静默跳到新版本。
5. 已上传文件不依赖电脑在线。未上传完成的文件仍需电脑重新连接；下载暂停后使用“继续下载”恢复同一 PDF/工作表变体；应用重启后从已落盘游标继续，校验失败重新下载。账号切换、退出及清理缓存会隔离或撤销后续写入。

## 持久协议

复用 Native `deliverables/presented`，`files[].result` 为可选 schema 1 清单，旧路径声明继续有效。清单包含 `id`、`version`、`turn`、可选 `previousHash`、`original`、`variants`、`previewState` 与 `warnings`。原文件和变体统一为 `{type: "file", attachment: {attachmentId: "sha256:<hex>", name, bytes}}`。变体角色为 `pdf`、`thumbnail`、`workbook` 或 `sheet`，`key` 在同一版本内唯一。

发布从源文件流式复制到附件存储，复制前后校验源文件版本；PNG 原图字节不变。版本从 1 连续递增，预览更新可以增加变体，不能替换原文件或已有变体。延迟预览仍归属原版本及轮次，不覆盖最新版本。恢复 Agent 会重新处理 pending 预览；插件销毁取消并等待后台任务结束。

Flyway V100 增加 `sync_results`，在接受事件的事务内投影；V101 增加手机聊天与电脑任务关联。事件重放保持幂等，分支仅获得实际继承的事件引用。服务端只允许当前账号读取所属任务、原文件与变体，不公开本地路径。既有附件上传按账号、哈希去重并验证完整字节。

## HTTP 接口

| 路径（均位于 `/api/account`） | 语义 |
| --- | --- |
| `GET /sync/result-capabilities` | schema、格式、对象和账号容量、Range 下载能力 |
| `GET /sync/sessions/{session}/results?after={eventSeq}` | 最新清单变更，事件游标分页；传输状态为查询时快照 |
| `GET /sync/sessions/{session}/results/{id}/versions` | 固定版本记录及实时传输状态 |
| `GET /sync/sessions/{session}/results/{id}/versions/{version}/files/{key}` | 指定原文件（key=original）或变体的二进制流 |
| `GET/POST /chats/{chat}/desktop-tasks` | 显式关联同账号电脑任务；重复请求幂等，不触发模型推理 |

二进制接口逐次鉴权，只返回已校验附件；未同步完整返回 409。支持单范围 Range、后缀范围、ETag、If-Range、304 和 416；返回 `nosniff`、`no-store` 与安全下载文件名。`ResultBlobReader` 隔离存储读取，当前实现通过 JDBC 定位包含起始字节的块，再以块偏移游标每次最多读取两块，SQL 本身使用 LIMIT 保证自动提交模式下客户端内存有界；空文件不取块，缺块和输出断流会中止，未来对象存储必须保持账号隔离、完整哈希校验与范围语义。

`after` 是清单事件游标，不是上传进度游标。iOS 打开版本页时每 5 秒刷新版本记录；同版本从准备中变为可预览时自动打开默认预览，上传尚未完成则在传输完成后重试。明确选择原文件和手动暂停会保留，刷新不会跳回旧版本或自动恢复已暂停下载；目录拉取完整分页快照，避免只读事件增量遗漏上传进度。目录按账号、任务缓存，离线明确标为已保存目录。旧版服务器仍支持普通附件入口，但固定结果查询要求部署 V100/V101 对应业务服务。

## 预览与资源限制

默认发布原文件 32 MiB，单预览 32 MiB，合计预览 64 MiB；最多 100 个结果、1,000 个已存版本/任务。XLSX 解析在独立 Worker 中进行，默认 30 秒超时、512 MiB 老生代堆上限，分别由 `workbookTimeoutMs`（最多 120 秒）及 `workbookHeapMiB`（64–2,048 MiB）配置。解析超过容量、超时或内存耗尽会返回预览失败而不终止主进程；取消会等待 Worker 退出。ZIP 预检最多 10,000 项、解压数据 64 MiB，工作表矩形面积及访问单元格上限 250,000，最多 100 个可见工作表，行窗口 100 行，单窗口 JSON 2 MiB，最多 250 个窗口；Worker 在传回主进程前限制 JSON 合计最多 64 MiB，并遵守更小的配置预览总量。隐藏工作表不导出；仅显示已有公式结果，不执行宏、公式或外部链接；未保存公式结果明确提示。数字/日期格式、列宽、粗体/斜体与合并信息保留；图表、图片和条件格式需查看原文件。手机每次显示最多 12 列及一个行窗口，合并跨窗口的部分按当前窗口裁剪。

Office 转换沿用 `officeToPdf` 的队列、超时、输入输出上限与缓存；FunnyWork 组合开启首页缩略图，默认 48 DPI、最大边长 720、最大 1 MiB。缩略图失败仍保留 PDF；缺字体时提示排版差异。PNG 缩略图限制输入 4,000 万像素；手机原图预览按最大 4,096 边长采样，分享仍使用完整原文件。

服务端默认每对象 32 MiB，每账号 1 GiB、10,000 对象；未完成上传也占配额。参考 `deploy/result-files.env.example`，修改服务器容量时同步调整桌面插件配置。iOS 下载使用服务器返回容量，并保留 256 MiB 客户端硬上限；已下载文件和未完成文件分别受缓存策略限制，未完成文件最多 32 项/256 MiB。磁盘文件使用数据保护并排除系统备份，逐块提交检查点，最终流式 SHA-256 校验。

## 部署与验收

先部署业务服务及 Flyway 迁移，再更新电脑端与 iOS。保留 `.local/`、Python 导入路径及现有附件存储。发布模块已挂载 standard、ptc、cordis 预设；需要附件本地提供者，Word/PPT 还需要可用 Office 转换器。不要将本地附件目录或原文件路径作为公网链接。

本地实施清单与验证记录按[贡献指南](../../CONTRIBUTING.md#配置与数据)归档。生产 PostgreSQL、Windows 原生转换及真机/系统分享面板需在对应环境验收。对象存储、无需电脑的服务端 Agent、Office 在线编辑和多人协作属于部署扩展，当前未启用。
