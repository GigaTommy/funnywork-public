# 统一身份认证与用户同步

本模块供私有化部署对接企业身份平台。认证和同步复用若依的 `sys_user`、部门、角色及会话，不创建第二套员工账号。当前提供 HTTPS 标准适配协议、手动全量与增量同步、持久化同步任务、自动增量计划、批次记录和账号状态校验。企业平台协议不一致时，应在企业侧部署转换接口，或实现 `DirectoryAdapter` 并调整 `DirectoryRegistry.adapter` 的适配器选择；当前配置只启用内置 HTTP 适配器。

## 独立本地用户

统一身份平台是可选集成。未配置平台时，管理员可直接在“系统管理 → 用户管理”新增本地用户，分配部门和角色，维护资料、重置密码、停用和删除账号。本地用户使用管理数据库中的密码登录，不请求外部认证 API；平台不可用不影响本地用户认证。

用户列表提供“账号来源”筛选并标明本地或统一身份来源。“新增本地用户”始终创建本地账号；外部同步不得接管同名本地账号。外部账号的密码由身份平台维护，后台不提供重置入口，接口也拒绝重置。两类账号共用本系统权限与业务授权规则，新增本地用户后仍需按实际用途授予权限。

本地部署未配置身份源时，可运行 `python3 scripts/checks/check-local-users.py` 验证创建、来源筛选、密码登录、重置密码及停用；脚本通过真实接口创建临时角色和用户，完成后清理，不输出凭证。需先启动业务与身份服务。

## 部署与升级

1. 备份管理数据库，停止身份服务，执行仓库根目录的 `scripts/setup/ruoyi-identity-directory.sql`，再依次执行 `scripts/setup/ruoyi-directory-jobs.sql` 、`scripts/setup/ruoyi-directory-previews.sql` 、`scripts/setup/ruoyi-directory-menu-fix.sql` 和 `scripts/setup/ruoyi-directory-audit.sql`（单事务），最后部署新版本。新增任务迁移用于队列、计划和独立身份源菜单。原 PostgreSQL 脚本可重复执行，增加 `sys_user.external_source` 和三张同步表，不修改已有凭证或角色。迁移还增加同租户未删除账号名唯一索引；若已有重名账号，需先核对并处理冲突，迁移不会自动改名或合并。所有身份服务实例都必须升级后再启用外部账号。
2. macOS 和 Windows 的本地准备入口均调用 `scripts/setup/prepare-ruoyi.py`，会自动执行上述迁移；正式部署需由数据库发布流程执行。此版本只提供 PostgreSQL 迁移。
3. 将 `deploy/identity-directory.example.json` 复制到服务器私有配置目录，配置身份源、所属租户、两个 HTTPS 地址及部门映射。`departments` 的键是外部稳定部门 ID，值是该租户现有且启用的若依部门 ID。
4. 将配置文件绝对路径写入环境变量 `FUNNYWORK_IDENTITY_DIRECTORY_FILE`；将接口访问凭证写入 `credentialRef` 指定的环境变量。配置文件只保存引用，不保存凭证明文。配置启动时加载，修改后重启服务；接口凭证在每次请求时读取 Spring 环境。
5. 超级管理员进入“工作平台 → 身份源”，提交首次全量同步。也可将 `funnyworker:directory:read` 和 `funnyworker:directory:write` 授予组织范围（全部数据权限）的角色；仅部门范围的角色不能操作身份源。为导入账号单独授予桌面权限与业务授权，再验证桌面登录。

未配置身份源时，本地账号维持原认证路径。已标记为外部来源的账号在身份源配置缺失时认证失败，不回退本地密码。禁用身份源可通过移除配置并重启实现，已同步账号和历史不会删除。

## 认证协议

服务端向 `authenticationUrl` 发起 POST，使用 `Authorization: Bearer <部署凭证>`，请求类型为 JSON：

```json
{"username":"alice","password":"用户本次输入的密码"}
```

成功响应为 HTTP 200：

```json
{"externalId":"immutable-employee-id","enabled":true}
```

账号密码无效返回 HTTP 401。`externalId` 必须与已同步账号绑定的外部 ID 完全相等；不接受通过用户名匹配另一个主体。HTTP 200 缺少 `enabled` 或外部 ID、超时、重定向和其他异常均不能建立会话。上游访问令牌不传给客户端，外部密码不保存到本地数据库或同步日志。

本地会话仍由若依签发。外部账号必须通过统一密码认证才能构建新会话；短信或其他现有认证策略不能绕过这一要求。本地若依账号保留原有登录方式。桌面启用若依管理认证后，失败不再回退到旧业务密码；原本通过 `FUNNYWORK_LEGACY_DESKTOP_USERNAME` 使用 `desktop-check` 的开发环境需改为配置正常若依账号，或在隔离开发环境显式关闭 `FUNNYWORK_RUOYI_ACCOUNT_ENABLED` 使用本地模式。该旧回退变量已移除。已有密码失败计数继续用于统一密码登录；平台不可用与密码错误分开处理。

## 用户查询协议

对 `usersUrl` 发起 GET，携带 URL 编码的 `checkpoint` 和 `cursor` 查询参数，以及同一部署凭证。首次全量同步的 `checkpoint` 为空；增量同步使用上次成功提交的检查点。

```json
{
  "snapshot":"stable-snapshot-42",
  "nextCursor":"",
  "checkpoint":"changes-through-42",
  "users":[
    {
      "externalId":"immutable-employee-id",
      "username":"alice",
      "displayName":"Alice",
      "departmentId":"external-engineering-id",
      "version":42,
      "enabled":true
    }
  ]
}
```

同一轮分页必须返回相同的 `snapshot` 和最终 `checkpoint`。`nextCursor` 为空表示已完成；非空时继续请求下一页。单页最多 500 人，最多 100 页、总计 10000 人；响应最多 1 MiB，拉取时间预算 120 秒。超限或分页循环会失败。完整拉取后再开启写事务，不会提交半批用户；当前失败重试从上次成功检查点重新拉取，不支持跨失败批次续传中间页。

用户 `version` 是上游单调递增的正整数。旧版本跳过，同版本相同内容幂等跳过，同版本不同内容报冲突。同批次重复外部 ID 或用户名报错。用户名和显示名最多 30 个字符，外部用户与部门 ID 最多 128 个字符。

## 账号与权限规则

外部账号唯一身份为“租户、身份源、外部 ID”。改名更新原 `user_id`，不会改变历史归属；同名本地账号或其他身份源账号会使整批同步失败，不自动合并。

初始化只创建员工资料，不分配角色、岗位、桌面权限或业务授权。更新只修改账号名、显示名、部门及外部状态；角色、岗位、密码字段和业务授权保持不变。缺少部门映射、部门不属于租户或部门已停用时，整批回滚。

`enabled=false` 会停用本地账号，不硬删除用户或历史记录。外部恢复启用不会自动撤销本地停用，需要管理员确认启用；这也保留管理员手动停用的决定。全量同步中缺失的用户不会被推断为离职，平台须显式返回停用记录。空全量结果拒绝提交；空增量结果可以推进检查点。

所有有版本更新的账号都会尝试退出旧会话。请求入口还会检查外部来源、状态和版本，避免会话退出暂时失败导致旧授权继续使用。停用传播时间取决于同步频率：只有同步成功后，本地才能获知上游变更。

## 管理接口与审计

接口位于身份服务，通过业务入口的 `/ruoyi` 代理访问，使用若依会话。超级管理员或具有组织范围身份源权限的管理员可调用，读取与维护权限分别校验：

`GET /funnyworker/identity-sources/access` 返回当前已登录账号的 `canRead`、`canWrite`，复用服务端组织范围与显式权限校验。不接受目标账号或租户参数，不授予权限。管理页面取得能力后才开放维护；读取失败保持维护禁用。前后端应配套升级，旧身份服务缺少该接口时页面提示读取失败。所有写接口继续在执行时独立校验实时权限。

| 方法 | 身份服务路径 | 用途 |
| --- | --- | --- |
| GET | `/funnyworker/identity-sources` | 当前租户的身份源标识和部门映射数量 |
| POST | `/funnyworker/identity-sources/{id}/sync?full=true` | 全量初始化或重新核对 |
| POST | `/funnyworker/identity-sources/{id}/sync?full=false` | 从成功检查点同步更新 |
| GET | `/funnyworker/identity-sources/{id}/runs` | 最近 100 个批次 |

旧同步接口同步执行，请求等待上限 180 秒；连接中断不表示同步失败，应先查询批次记录。记录包含发起人、模式、状态、时间、新增/更新/跳过数量和脱敏错误代码，不包含外部密码或接口凭证。事务失败不推进检查点。并发批次使用源版本校验，后提交的旧快照拒绝覆盖已提交结果。

服务意外停止可能留下未完成任务；旧同步接口仍会在下一次调用时处理超过 180 秒的 `FETCHING` 批次。新页面使用持久化任务接口。后台任务每 10 秒检查队列；执行超过 5 分钟仍未完成时，先核对关联批次是否已经成功提交，再恢复或标记失败。

## 当前验收范围与后续工作

自动测试覆盖模拟 HTTPS 客户端、配置约束及测试数据库中的同步事务、幂等、改名、冲突、停用、版本与会话校验。真实身份平台协议、私有证书链、生产 PostgreSQL 数据及桌面端到端登录须在目标环境联调；不能用模拟测试代替该验收。

后续待实现：客户平台专用适配、部门目录自动建树、大规模任务队列和分页断点续传、逐条失败重试。本版采用整批原子提交，错误修正后重跑整批。

## 后台任务与自动计划

直接同步通过 `POST /funnyworker/identity-sources/{id}/jobs?full=true|false` 提交任务，返回已持久化的任务编号。同一租户和身份源已有排队或执行中的任务时，请求模式一致时返回该任务，不重复创建；全量、增量或预览模式不同则返回冲突，需等待原任务完成。GET 同路径返回最近 100 个任务；通过 `run_id` 关联批次。页面轮询不影响后台执行。

`GET/PUT /funnyworker/identity-sources/{id}/schedule` 查询和保存增量计划。PUT 请求为 `{"intervalSeconds":3600,"enabled":true}`，范围为 60 至 86400 秒。后台执行前重新检查发起人的账号、组织范围和写权限；权限撤销后不继续执行，计划自动停用。计划基于服务端时间；单实例顺序执行，不承诺准点开始。

连接等暂时失败最多尝试 3 次，按尝试次数延迟 60 秒、120 秒；资料冲突不自动重试。批次已提交而队列状态未更新的中断恢复不会重新拉取用户。任务和批次仅保存脱敏错误代码。升级前必须执行新增迁移；迁移未就绪时后台停止本轮处理并提示检查数据库。

## 同步预览与确认

页面的“预览更新”和“预览全量”分别调用 `POST /funnyworker/identity-sources/{id}/previews?full=false|true`，通过持久化队列生成预览，返回任务编号。任务的 `run_id` 是预览编号。预览不会写入用户或推进检查点；自动增量计划仍按管理员启用的计划直接执行。

`GET /funnyworker/identity-sources/{id}/previews/{preview}` 返回数量与分页明细，支持 offset 和 limit（1 至 100）。明细包括新增、更新、停用、跳过与冲突原因。预览不保存密码或接口凭证。停用数为更新数的子集；新增的停用账号在明细中显示上游状态。

`POST /funnyworker/identity-sources/{id}/previews/{preview}/confirm` 应用持久化的同一份快照。确认前再次校验组织权限、源配置摘要、同步代数、本地相关账号与部门状态；存在冲突或变更时要求重新预览。确认过程在同一数据库事务中完成，并锁定相关已有账号与部门，防止校验与写入之间覆盖并发本地变更。成功后重复确认返回已应用，不重复创建账号或推进检查点。

预览有效期为 24 小时，后台在过期后清除用户明细与快照，仅保留数量、状态和审批记录。页面读取不返回快照、检查点或内部校验摘要。已应用的预览同样清理个人资料，保留汇总记录。界面与服务端均独立校验读、写权限。


### 历史权限菜单编号修复

`ruoyi-directory-menu-fix.sql` 将身份源维护固定为 8121，桌面使用权限保留 8120。若旧库的 8120 已表示身份源维护，迁移先移动该权限对应的角色与租户套餐引用，再恢复桌面菜单，避免把原同步管理员误授权为桌面使用者。若 8120 已表示桌面使用，仅增加缺失的身份源维护菜单，不自动为现有角色增加同步权限。脚本可重复执行；遇到保留编号被其他权限使用会中止，需核对实际菜单后处理。macOS 与 Windows 共用的准备入口会在原同步迁移之后执行此修复。

可在隔离 PostgreSQL 实例执行 `python3 scripts/checks/check-directory-menu-migration.py --port <测试端口>`，用独立随机 schema 验证新安装、两种历史编号含义、重复执行与保留编号冲突；测试结束会删除该 schema。可通过 `--psql` 指定客户端路径。


## 同步批次审计

`GET /funnyworker/identity-sources/audit` 同时要求 `funnyworker:audit:read` 与组织范围身份源读取权限。参数 `from`（含）、`until`（不含）为毫秒时间戳，区间最多 93 天；可按 `source` 或精确 `reference`（任务/批次编号）筛选，`limit` 为 1 至 100，后续页传回 `nextCursor`。

任务和每次执行批次分别展示，返回查询时的状态、有限计数与错误代码；已确认预览附带确认人和应用时间。不读取账号快照、计划正文、上游检查点或凭证。失败重试的旧批次保留，但任务的关联批次为最近一次尝试。分页返回各次查询时的状态，多页读取期间任务状态可能更新；核对最新状态时重新查询。已移除配置的身份源历史记录仍可按租户权限查询。管理端关联审计页保留业务事件与身份同步两个独立来源。
