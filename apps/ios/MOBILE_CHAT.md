# 手机聊天与电脑任务

## 产品行为

登录后默认进入文字聊天首页，底部始终提供输入框、模型选择和发送按钮。首页无需选择设备或工作区，也不要求电脑在线。采用奶白与中性灰主题并支持系统深色外观、键盘避让和 iPad 布局。

“电脑任务”保留原有桌面会话目录和远程交互：查看进展、回答问题、处理审批、发送新指令与停止。创建和执行工作任务必须由在线电脑的 Harness 完成。手机聊天不提供本地文件、Shell、工具调用或 Agent 预设执行；不会创建电脑工作任务。两种对话使用独立记录，手机聊天目前不写回桌面 Harness 会话日志。

## 模型与思考选择

聊天输入区仅显示紧凑的模型设置图标。点击后打开可滚动列表，显示当前完整模型名称、按厂商分组的可用模型，以及后台声明支持的 Off、Low、High、Max 思考档位。长名称仅在弹层内换行，适配小屏、大字号和 iPad。下一轮选择按账号和模型保存；待发送记录冻结当时的档位，重启核对不改写它。

手机聊天复用后台已发布的 Messages 和 Chat Completions 模型。`GET /models` 返回 `protocol`、`reasoningEfforts` 和 `defaultReasoningEffort`，`POST /{id}/turns` 可携带 `reasoningEffort`；旧客户端省略时沿用旧行为。调用方可用 `maxOutputTokens` 明确限制本轮输出和费用预留，必须为 128 至当前账号模型输出上限；该值也纳入幂等校验。服务端验证模型支持，并分别发送 `output_config.effort` 或 `reasoning_effort`，Off 显式禁用思考。客户端与后台只把流中的正文写入回复，思考流不会混成正文。

## 模型与用量显示

聊天顶部显示最近一轮实际模型及累计已确认 token，每轮回复展示实际模型与输入/输出明细。输入包含缓存命中，缓存作为其中明细展示，不重复加到总量；累计依据后台各轮次账本，不累加流式事件或刷新次数。使用已下线模型的旧记录仍显示原部署名称；模型选择器作用于下一轮，已执行模型按各轮账本显示。部分尝试缺少完整 usage 时明确标注未确认，不显示成零。服务端没有完整 usage 时，客户端不自行估算。

## 后端接入

`MobileChatsController` 提供账号级 `/api/account/chats` 接口。全部初始请求使用现有账号鉴权，按租户及不可变账号标识隔离；设备凭证不能作为用户凭证使用。只返回显示名称与模型标识，上游凭证留在服务端。

| 接口 | 行为 |
| --- | --- |
| GET `/models` | 当前有权使用的聊天模型，暂停容量标为不可用 |
| GET 根路径 | 兼容入口，最近 100 个未归档聊天摘要 |
| GET 根路径 `?history=true` | 分页历史；支持 `archived`、`query`、`after`，每页最多 50 条 |
| GET `/{id}/history` | 本账号聊天的当前标题、归档状态及独立历史版本 |
| POST `/{id}/history` | 幂等重命名、归档或恢复，携带请求 ID 和预期历史版本 |
| GET `/{id}` | 对话、最多 100 轮消息与最近票据状态、用量 |
| POST `/{id}/turns` | 以固定轮次 ID、模型、文本和预期 revision 准备请求；重复同一内容恢复原票据 |
| POST `/{id}/turns/{turnId}/execute` | 消费许可一次，流式回复；重复执行拒绝 |
| POST `/{id}/turns/{turnId}/cancel` | 取消等待或请求停止当前推理 |

所有聊天复用 `ModelMiddleware` 的权限、资源池、准入、公平调度、等待期限、执行尝试及用量账本。管理后台原有容量、队列和用量页面可查看调用，队列用途显示“手机聊天”，任务标识为聊天 ID。手机不是另一套计量来源。

- 私有模型：现有推理开关启用后，使用有权访问的 `CHAT_COMPLETIONS` 部署（DeepSeek/千问等）；不自动打开私有推理开关。真实模型的流式 usage 和 OpenAI-compatible 协议仍需实际服务联调。
- 当前公网测试：复用后台已发布的 DeepSeek 配置，在服务端登记版本绑定的聊天部署。每租户/授权区域初始池为执行 2、用户执行 1、队列 1000、用户等待 3、等待期限 120 秒。管理员可调整或暂停；该初始策略需要按实际硬件和模型的容量测试结果调整。
- 公网聊天部署不进入 Harness 普通模型目录，避免被电脑工具任务误选。版本变化停用旧路由；已存在的账本记录保留用于核对。
- 仅成功且完整保存的历史轮次进入后续模型上下文。文本上限 16000 个 UTF-16 单元，最多 100 轮；输入采用保守字节预算，并预留输出空间。达到限制提示新建聊天，不静默截断上下文。

## 恢复、停止与数据

回复终态与账本终态在同一事务提交。回复写入失败会回滚账本终态，保留执行记录等待原有恢复核对；不重新调用上游。查询时发现已经成功但未保存回复的孤立记录，会将聊天轮次标为失败、保留实际账本计量，使用户能够继续对话。

V88 创建独立 `mobile_chats` 和 `mobile_chat_turns` 表。服务端从真实上游流保存回复，不采信客户端上报的助手文本或 token 数；请求按部署的 `streamUsage` 能力决定是否发送 `stream_options.include_usage`；不支持时省略该参数。没有完整 usage 时仍允许完整回复成功，沿用账本的缺失/未知标记，不用字符数伪造用量。超出回复保存上限或空回复标为失败。

手机进入后台或断网，已经开始的推理继续受统一容量与十分钟执行期限控制，并保存最终回复。回来后查询原票据，不重新执行。请求是否执行无法确认时显示“结果待确认”；管理员按原账本流程核对，上游停止未确认时不盲目释放容量。开始执行前失败可回到编辑，保留草稿。等待取消后释放许可；运行中停止是否完成以后台结果为准。

本地只在既有账号隔离、受文件保护的缓存中保存聊天草稿、快照和待核对记录；退出账号后不会继续写入原账号。服务端聊天正文与请求历史属于持久业务数据，应纳入现有数据库备份、访问控制和保留策略。新版历史接口支持分页及归档恢复，兼容入口仍为最近 100 条；未提供删除接口。

Servlet 流式断连收尾仅放行两个模型执行路径的内部 ASYNC 延续及携带原执行路径的 `/error` INCLUDE，初始 HTTP 请求仍认证，匿名执行负向测试覆盖。原理参考 [Spring Security 调度授权说明](https://docs.spring.io/spring-security/reference/6.5/servlet/authorization/authorize-http-requests.html)。

## 上线顺序

1. 备份数据库，先部署包含 V87（电脑模型目录）及 V88（手机聊天）的业务服务。
2. HTTPS 入口放行 GET/POST `/api/account/chats`、`/api/account/chats/`；聊天流禁用缓冲、读超时至少 660 秒，其他管理入口继续私有访问。参见 `deploy/nginx/funnyworker.conf.example`。
3. 检查后台模型发布或私有 CHAT_COMPLETIONS 部署及服务端凭证；按实际模型/GPU 压测设置容量。没有可用模型时首页显示原因并阻止发送。
4. 发布新版 iOS；升级桌面客户端完成 V87 目录同步。仅手机聊天不依赖桌面升级或在线。
5. 使用真实账号、模型服务、签名真机完成下列验收。模拟器样例用于开发检查；生产服务和 APNs 在目标环境用真实账号及设备验收。

## 自动化检查

`MobileChatTests` 覆盖流解析、缓存账号隔离、固定轮次恢复、等待停止、恢复不重放、失败后编辑。`MobileChatHomeUITests` 在明暗主题验证首页输入发送、收到回复、等待与停止、电脑任务入口往返；`ModelManagementUITests` 验证电脑模式的模型/预设和容量状态。

`MobileChatsIntegrationTest` 使用真实 HTTP 服务、Flyway 迁移后的 H2（PostgreSQL 模式）数据库和本地模拟推理节点，验证没有桌面设备也能聊天、多轮上下文、隔离、幂等与单次执行、鉴权、队列取消和用量落账，并通过 TCP 强制断连验证服务端仍保存最终回复。公网目录测试不会实际调用公网 DeepSeek。

从根目录运行：

```sh

  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath .local/ios-build CODE_SIGNING_ALLOWED=NO \
  -parallel-testing-enabled NO -only-testing:FunnyWorkTests \

  -only-testing:FunnyWorkUITests/ModelManagementUITests test
```

## 真实环境 UAT 脚本

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 电脑关闭 | 所有电脑退出，手机登录、选模型并发送 | 无设备/工作区要求；正常回复；后台用途为手机聊天 |
| 多轮与历史 | 发送两轮关联问题，离开后从聊天记录打开 | 保留上下文、无重复气泡；旧记录可读 |
| 模型权限 | 后台撤销模型或账号区域授权后发送 | 服务端拒绝；不执行未授权推理 |
| 无模型与暂停 | 清空发布/暂停容量池，刷新首页 | 不提供虚假可用模型；明确不可用或等待状态 |
| 容量等待 | 将实际池设为 1，两个账号同时请求 | 一次推理执行，另一请求等待；后台队列正确 |
| 队列限额 | 增加等待至用户/全局上限 | 明确拒绝新请求，已接纳请求继续；草稿可编辑 |
| 等待取消 | 等待中点击停止，再核对队列 | 原票据取消且不调用上游；草稿保留 |
| 运行停止 | 输出期间停止 | 及时请求上游停止；未确认时显示待核对，不再次执行 |
| 断网与后台 | 回复期间切后台/断网，随后恢复 | 读取原请求结果，完整保存回复，执行次数没有增加 |
| 重复与双客户端 | 对相同 ID 重复提交/执行；另一手机打开运行中聊天 | 准备幂等、执行仅一次；另一端只观察 |
| 账号隔离 | A 登录并聊天后退出，B 登录 | B 无法读取 A 正文、草稿及票据 |
| 用量核对 | 完成聊天后核对推理节点 usage 和后台账本 | 同一实际尝试只计一次；缺失 usage 明确标注 |
| 长文本边界 | 超长输入或用完上下文 | 阻止提交或提示新建，不发送截断内容 |
| 电脑任务监控 | 打开电脑任务，选择在线 Mac/Windows 会话 | 展示进度与容量等待；手机没有本地工作执行 |
| 电脑交互 | 回答 Harness 问题/审批并发送新指令 | 由来源电脑处理，原 epoch/幂等规则有效 |
| 电脑离线 | 关闭电脑后尝试发送工作指令 | 不显示已执行，不转为手机聊天执行 |
| 推送导航 | 点击真实电脑审批/结束通知 | 进入对应电脑任务，返回后保留聊天 |
| 明暗与平板 | iPhone/iPad，明暗主题，键盘开关，横竖屏 | 输入发送可达，文字对比正常，入口无重叠 |

实际 UAT 需记录账号、模型/部署版本、票据 ID、操作时间、界面截图和服务端结果；不要把密钥写入记录。

## 底部模型与用量菜单

手机首页与聊天输入区复用模型菜单，显示名称及具体模型标识，选择只影响下一轮；运行时禁用切换。聊天底部提供会话用量胶囊，每条已执行回复提供本轮明细入口；详情显示实际执行型号、输入总量、输出、缓存读取和加权命中率。窄屏与大字体可换行，iPhone 使用半屏详情。极大字号下，底部指标菜单与发送图标限制到 XXXL，正文和明细继续跟随系统字号；输入区最多显示两行并可滚动，避免遮挡操作。电脑任务输入区使用相同明细组件，统计源仍为来源电脑 Harness 投影。

后台 Chat Completions 输入已包含缓存；手机总量等于输入加输出。桌面投影输入为未缓存桶，映射时加入缓存读取和写入一次。缓存命中分子只包含读取，写入不能算命中；会话百分比使用已知缓存读取之和除以对应输入之和。缺失缓存字段保留未知，不显示零；缺失用量不估算。部分覆盖显示已知调用口径与未确认提示。失败/取消但用量完整的执行仍计入，刷新恢复不重复累计。

后端适配标准 cached_tokens 与 DeepSeek 原生 prompt_cache_hit_tokens / prompt_cache_miss_tokens，双字段冲突或非法数量标记 PARTIAL。性能指标使用服务端有效输出事件及执行账本，详见下文。

验收补充：打开会话与本轮明细，核对具体型号；模型切换后历史实际型号保持；100 输入命中90与900输入命中90的会话命中率为18%，不能平均成50%；未知缓存不作为零；桌面缓存写入不计入命中分子；明暗、iPad与键盘状态下底部操作可达。

## 耗时与输出速度

可行性：业务账本已有准入、获准、执行、结束和首个响应字节时间；Harness sessionStats 投影已有模型/工具耗时、首个输出与生成统计。首个字节可能是空事件，不能作为首字。V89 增加 nullable first_output_at，流式解析器只在非空正文、推理或工具参数输出时记录一次；非流式响应不伪造首字时间，旧记录保留未知。

手机聊天已成功完成调用的统计：queue=granted-created，dispatch=started-granted，request=ended-started，total=ended-created；first_output=first_output_at-started；decode=ended-first_output_at。排队和获准后客户端提交等待均独立列出，不计入模型请求时间。输出速度=同一组有效调用的输出 token 总和 / decode 秒数总和，不能平均每轮速度；只有完整 usage 和正生成区间才参加速度统计。首个输出包含推理事件，生成区间含上游网络和尾部流式处理；这些是网关观测指标，不是 GPU 纯解码速度，也不是手机接收网速。

失败、取消、未知执行不作为已完成性能样本；时间缺失或顺序异常不显示伪造数值。完成但没有缓存/usage的调用仍可显示可靠耗时，缺失 output 则不显示速度。首个输出延迟仅在有效样本之间取均值，详情显示有效样本数和范围说明；恢复/分页不重复累计。

电脑任务直接读取 sessionStats：llmMs、toolMs、ttftMs/ttftSteps、decodeTokens/decodeMs；不从手机消息加载时间或当前可见分页推算。桌面投影不含队列与用户工具交互总墙钟时间，不显示这两类未知指标。

验证：空 role/空正文/usage/心跳不能触发首个输出；首个非空推理输出可以触发；累计 usage 不能重复计量；零生成区间、未确认 usage、失败 UNKNOWN、时间倒序不显示速度；5tokens/0.4s与35tokens/1.6s加权为20tok/s；手机/电脑明细以及大字体键盘布局均需验证。

## 首页简化布局

模型选择位于输入框外的工具行，使用无边框、无底色的小字号文字菜单。菜单按钮使用单层暖灰圆角底色，iOS 26 隐藏系统工具栏附加背景，点击区域仍为 44pt。网络刷新失败不在首页中央显示错误；持续两秒后显示顶部黄色连接状态点，点按查看真实原因并重试。正常恢复后状态点隐藏，草稿保留。权限、存储错误及待核对的发送结果仍保留明确操作提示。

## 手机聊天交互优化

手机聊天按服务端更新时间排列历史，并优先显示需要处理或运行中的聊天。回复更新只在阅读最新内容时跟随；上翻阅读旧消息时显示新消息入口，按账号和聊天保存阅读位置。旧缓存缺少时间时仍可读取，不虚构日期。

消息支持复制、选择文本、分享和朗读，本轮用量收在更多菜单。首页与聊天使用同一输入组件，支持展开编辑；运行期间可以写下一条草稿，仍须等待当前回复结束再发送，不新增同聊天排队或立即补充协议。停止、失败和旧请求完成不覆盖新草稿。

设置提供发送后保留键盘与使用帮助，首页建议追加或替换前保留当前草稿。交互约定见[设计规范](../../DESIGN.md)；可重复验证入口见[测试与调试](TESTING.md)。本地方案和验收记录按[贡献指南](../../CONTRIBUTING.md#配置与数据)归档。

## 手机历史管理

搜索入口位于聊天侧栏，按当前归档范围匹配聊天标题、用户消息和已保存回复；新版服务为每个聊天返回最近一次正文命中的消息引用、摘要和轮次创建时间；没有正文命中时返回标题摘要。手机结果突出命中文字，点按定位到对应用户消息或回复的开头，并可用顶部搜索按钮返回原查询及选中的结果位置。长消息不自动定位到其中的具体词语。标题命中保持正常阅读恢复行为。更早聊天通过“加载更多聊天”继续读取，分页失败保留已经加载的记录并从原游标重试。刷新按钮重新读取首批记录；普通回复完成只合并已加载列表，不重置历史分页。

长按记录可重命名或归档，归档范围内可恢复。归档保留正文、草稿、阅读位置和已接纳的执行；已开始的回复与停止、核对仍可进行。新轮次须恢复后发送，重复的已接纳发送请求仍返回原轮次。

V99 增加 mobile_chats.archived 和 history_revision，并保存历史操作回执。历史版本与推理 revision 独立，重命名、归档不改变已开始的回复请求。更新提交携带稳定请求 ID 和预期历史版本，按租户与账号核验归属；同 ID、同内容重试返回原回执，冲突内容或过期版本拒绝。客户端按账号保存未确认的原请求，重启后用户可核对；不会自动创建新请求重放。核对旧回执后还会读取当前元数据，避免覆盖另一设备后续修改。

分页使用更新时间降序与 ID 升序的游标，绑定搜索与归档范围。文本搜索把百分号、下划线和感叹号作为字面字符。列表为实时视图，分页期间的聊天更新可能改变位置，客户端合并去重，刷新可重新核对列表；不提供冻结整个历史目录的快照。单个聊天的既有 100 轮上下文上限保持不变。

先升级业务服务并由 Flyway 应用 V99，再更新 iOS。旧客户端继续使用最近 100 条兼容入口；新客户端连接旧服务时只搜索最近加载的标题，明确标注范围，隐藏归档和重命名入口。V99 扩展了表结构，旧服务包的按位置写入语句不能直接配合该结构回滚，应使用相应版本的服务与数据库。

本批为隔离业务服务测试及原生模拟器验收，未对生产数据库应用迁移，也未更新真机。

### 搜索命中兼容性

历史分页返回 `searchHits: true`，有搜索词时每个摘要可附 `search_match`：`field` 为 title／user／reply，正文带 `turnId`，`excerpt` 为限长片段，`created_at` 为轮次创建时间（标题命中使用聊天更新时间）。每个聊天呈现最近一个正文命中，用户消息和回复同时命中时采用用户消息；该能力不返回同一聊天的全部命中列表。摘要保留 Unicode 字符边界，百分号、下划线与感叹号继续按字面匹配。服务端对当前页批量读取命中，未逐聊天请求全部正文。

无需新增迁移，沿用历史管理的 V99 结构。先升级业务服务，再更新 iOS；旧客户端忽略新增字段，新客户端面对缺少命中引用的历史服务仍打开聊天，不承诺直接定位。搜索定位沿用已授权的聊天快照，单个聊天最多 100 轮，快照包含全部轮次；目录分页与聊天轮次上限是两项不同限制。命中暂不可用时保留查看对话与返回搜索入口，不改写输入或执行版本。
