# iOS 测试与调试

供开发与测试人员使用。构建与签名见 [README](README.md)，交互要求见 [客户端行为参考](CLIENT_REFERENCE.md)。模拟器联调使用本地开发后端、隔离数据和专用测试账号；生产检查使用单独授权的账号与环境；本地回归使用隔离数据。


真实 HTTPS 入口可先做不带凭证的原生 iOS 检查；需要已启动的模拟器，脚本不启动应用、不登录、不修改服务端数据：

```sh
sh scripts/checks/check-ios-service.sh https://your-service.example SIMULATOR_UDID
```

检查使用模拟器原生 `URLSession`、系统证书校验和拒绝重定向的策略，要求账号与目录接口返回 401、`UNAUTHENTICATED` 和禁止缓存响应。命令行 HTTP 工具可能被边缘防护单独拦截，其结果不能代表 iOS 请求。登录权限、接口版本、附件上传与桌面执行在后续账号联调中分别检查。

`APITransportTests` 通过独立的 `URLProtocol` 响应运行实际 `URLSession` 请求，验证登录 JSON、令牌头、分页参数、DELETE 空响应、401／403／409／500、无效 JSON 与传输取消；重定向测试直接验证委托拒绝转发。测试使用模拟响应；目标环境另检查 HTTPS 证书、网络配置、真实账号和桌面端到端流程。生产请求继续使用临时会话配置。

`CameraCaptureTests` 验证权限拒绝、无相机、取消后的迟到授权、照片一次性消费及 JPEG 像素和方向信息。拍照界面测试使用 `--ui-test-upload --ui-test-camera` 注入照片结果，验证草稿、上传就绪、重启恢复和不自动发送；附加 `--ui-test-camera-cancel` 验证取消不会改变已有附件。模拟器不验证真实相机拍摄或系统相机权限弹窗。

`ConversationReadTests` 验证已读边界持久化、后续更新、账号隔离、退出清理、旧页面不能倒退边界和旧目录兼容；界面测试覆盖读后清除、重启恢复及恢复旧阅读位置时保持更新提示。


`DeviceDirectoryTests` 验证旧响应兼容、设备撤销、网络失败后停用操作、恢复与迟到响应隔离，以及指定设备优先于记忆位置；界面测试覆盖设备选择、工作区选择、创建跳转和离线设备禁止创建。

`AccessibilityUITests` 使用系统最大辅助功能字号验证浅色／深色登录页和多行输入，检查完整草稿保留、输入区域高度、键盘收起与发送，并保留截图供布局核对。

`LoginUITests` 使用 Debug 专用的 `--ui-test-login` 入口，验证浅色／深色登录页的小 Logo、空表单禁用、密码显示切换、失败后保留输入、提交中防止重复操作、默认隐藏服务地址、登录帮助中的自建地址校验、网络错误恢复，以及登录进入列表和退出后的表单重置。该入口使用独立临时目录和模拟响应，不读取真实钥匙串、不访问网络；截图保存在测试报告的 `login-light`、`login-dark`、`login-error-light` 和 `login-error-dark` 附件中。真实身份认证仍需账号联调。

`AccountTests` 使用内存凭证与独立临时目录，覆盖恢复账号期间退出、旧登录响应／鉴权错误迟到、登录请求期间退出，以及相同令牌在不同服务或账号间的错误隔离，不读取真实钥匙串或连接服务。

`FunnyWorkTests` 覆盖分页连续性、最近记录定位、草稿与请求恢复、操作结果核对、来源变更与超时禁止重放、审批／问答关联、文件保护存储边界及账号隔离，另覆盖离线缓存恢复、容量边界、断网重连与消息排版解析，以及附件分块校验、损坏文件拒绝、取消下载、离线重开和账号隔离，以及新建对话的请求恢复、过期／实例变化禁止重发、结果跳转、上次成功位置恢复／账号隔离、离线或失效位置禁止自动切换、刷新保留手动选择和旧页面延迟回执隔离。图片缩略图测试覆盖校验、尺寸限制、缓存离线读取、账号隔离、损坏内容拒绝、取消下载及排队取消；界面测试验证缩略图、完整预览和离线重开。存储测试覆盖占用统计、账号隔离、清理后草稿与消息保留、迟到下载禁止写回及清理后重新下载；界面测试覆盖取消确认、清理和重启后的占用状态。消息附件测试覆盖引用校验与去重、旧缓存兼容、长度不一致拒绝、按引用重试、取消查询、离线预览及账号隔离；界面测试覆盖消息内点开预览和离线重启后再次打开。上传测试覆盖确认丢失后的续传、取消后的迟到响应、移除确认丢失、仅附件发送、失败草稿恢复及账号隔离；会话测试覆盖旧页面回执不能覆盖新的待确认请求，并验证运行提示只使用新鲜在线状态、排队消息与当前实例匹配，以及接受／未知结果后的展示变化。消息测试覆盖嵌套列表、续行、任务状态、分隔线与代码原文保留，以及表格边界、朗读暂停恢复、旧完成回调隔离和中断清理；目录测试覆盖本地日期及夏令时边界、置顶持久化与账号隔离、保存失败回退；搜索测试覆盖完整分页、失败后继续、旧查询结果隔离、附件名称匹配与同一消息去重；界面测试覆盖按附件名搜索并打开预览；语音测试覆盖识别结果结束、权限失败与旧回调隔离。`FunnyWorkUITests` 使用独立的本地样例验证真实 SwiftUI 页面上的审批、问答、立即补充、导航、消息选择与复制、表格横向滚动、朗读控制、语音文字确认与草稿追加、对话内搜索、置顶重启恢复、长对话初始定位／新消息提示／底部跟随、外观设置持久化，以及重启后的草稿恢复，不会连接实际服务或操作桌面。附件上传界面测试通过注入文件选择结果验证重启恢复和仅附件发送；系统照片选择器已在模拟器实测导入、缩略图、剩余数量限制与取消选择；照片单元测试覆盖图片类型识别、临时文件消失后的持久化、损坏内容拒绝、取消读取后的迟到结果及部分读取失败。系统文件选择器、iCloud 照片／文件提供方及真实账号端到端流程仍需真机联调。

登录页默认显示品牌、欢迎语、表单和连接状态；服务地址仅在登录帮助的自建服务配置中显示。空状态和操作提示采用简短的用户用语；中英文同步维护，见根目录 `DESIGN.md`。

Debug 构建可以通过启动参数 `--ui-test-conversation` 打开交互预览；添加 `--ui-test-questions` 预览问答，添加 `--ui-test-reset` 清理样例数据；`--ui-test-upload` 显示附件上传样例；`--ui-test-message-file` 显示仅附件消息；`--ui-test-message-image` 显示图片消息；`--ui-test-queued` 显示运行与排队状态；`--ui-test-rich-text` 显示排版样例，`--ui-test-lists` 显示嵌套任务清单，`--ui-test-nested-markdown` 显示列表内的段落、代码、表格和引用，`--ui-test-links` 显示网页链接，`--ui-test-live-reply` 显示生成中回复，`--ui-test-activity` 显示工具活动与失败结果，`--ui-test-offline` 模拟断网（先以同一示例正常打开一次，再不带 reset 重启）。`--ui-test-directory` 打开列表筛选预览，添加 `--ui-test-creation-locations` 可选择多个设备和工作区，配合 `--ui-test-creation-offline` 验证上次设备离线，可配合 `--ui-test-storage` 写入设置页的下载样例。这些入口不编译进 Release。测试报告中的 `approval-light` 和 `question-form` 附件保留界面截图。

真实联调还应覆盖桌面先处理审批、Host 重启、手机断网与回到前台、账号会话失效以及 macOS／Windows 的来源设备行为。

## 已有账号的 UI 联调

已授权账号的 UI 联调使用 `LiveNativeUITests`，默认因缺少私有配置路径而跳过。必须构建独立 `com.funnyworker.ios.liveui` 模拟器包，设置 `FUNNYWORK_IOS_BUNDLE_IDENTIFIER`，保留原 App 的账号、缓存和草稿。通过测试 runner 的 `FUNNYWORK_LIVE_UI_CONFIG` 传私有 JSON 文件路径，配置含授权账号、固定官方入口及两条既有 UAT 任务之一；不要把密码放入启动参数。DEBUG 的 `--live-ui` 与 `FUNNYWORK_LIVE_UI_ORIGIN` 只固定实际网络入口，不使用 fixture/reset 分支。原始 XCTest 输入日志和结果按私有文件保存，交付仅选取登录后截图。

该用例可用 `reviewSequence` 定位既有真实 diff 消息，通过正常搜索和上下文进入逐行审阅，验证行引用去重、文件意见重启恢复及加入草稿；不会发送意见。它与 `eventID` 的新审批步骤分别执行，不把审阅通过当作审批通过。`test-without-building` 也必须显式传 `-derivedDataPath .local/ios-build`，以免 Xcode 把测试结果写入系统盘的默认目录。

电脑命令仅将 POST 返回的精确 `409/SYNC_DECISION_EXPIRED`、`409/SYNC_DEVICE_OFFLINE` 视为未入队的明确拒绝；按账号和会话持久保留最近 20 条命令对应的本地拒绝原因，刷新或重启后仍显示拒绝并阻止旧审批再次提交。原草稿与附件保持；其他冲突、超时和缺失回执仍按结果未知处理，不据此推断成功或重发。

包含真实钥匙串保存的模拟器验收需要带实际开发团队标识的本地签名构建：`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=YES DEVELOPMENT_TEAM=<本机团队>`；不需要注册设备或更新描述文件。编译检查可使用无签名构建；真实登录和安全存储检查使用上述带团队标识的签名配置。
