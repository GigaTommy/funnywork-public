# 客户版本说明模板

供发布负责人填写，按 [文档管理规则](../CONTRIBUTING.md#文档管理) 审核。下方是模板，不是实际发布公告；没有可核实的版本、平台和分发状态时，不对外发布。

## 发布身份

| 项目 | 填写内容 |
| --- | --- |
| 产品与版本 | FunnyWork、具体客户端或服务端、完整版本／构建号 |
| 发布日期与渠道 | 实际发布日期；官网、企业交付、更新通道或 TestFlight |
| 适用平台 | 操作系统、CPU 架构、必要的最低版本 |
| 对比基线 | 上一公开版本或该客户正在使用的交付版本 |
| 可用状态 | 已开放下载、分批开放或审核中；未开放平台不能写成已发布 |

## 本版变化

只保留实际存在的条目，每条用一句话说明场景和结果，必要时解释客户需要采取的动作。

- 新增：该版本首次交付、用户现在可以完成的操作。
- 改善：已有操作在效率、可读性或恢复方式上的具体变化。
- 修复：触发问题的条件和修复后的可观察行为。

例如，额度问题可写“修复其他任务临时占用额度时，新请求被误报为余额不足的问题。”不要写成“实现持久化预算账本、跨池调度和全局锁校验”，后者属于技术说明。

## 升级要求与已知限制

说明是否需要重新登录、配套后端版本、用户数据处理或管理员操作。列出影响本版本使用的已知限制及可行替代方式；没有升级动作或新增限制时省略对应段落。

PDF 改善应明确适用范围，例如新生成文档，不得写成所有历史文件都会自动修复。后端发布与客户端发布分开写，不能以服务已上线代替安装包可用。

## 获取与支持

填写经过核实的官方下载入口或企业分发方式，以及适用的客服／组织管理员入口。不要提供私有源码仓库、内部 staging、数据库备份或验收资料链接。

## 发布前核对（内部使用，发布正文删除）

- 每条变化能对应源码、验证证据和实际分发版本，排除未随包交付的改动。
- 中英文分别表达同一事实、版本和限制，避免逐字翻译形成歧义。
- 产品常规能力、未来计划、需求对话、竞品比较、提交清单和测试流水均未混入正文。
- 安装包已验签；涉及外部审核的渠道已确认可用，审核中不写成已发布。
